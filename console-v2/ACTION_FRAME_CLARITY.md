# 动作帧清晰度审查

## 运行

在项目根目录执行：

```powershell
python console-v2/audit_action_clarity.py
```

默认报告写入 `.qoder/action-clarity-report/`，包括：

- `index.html`：动作概览和接触表入口。
- `sheets/<动作 ID>.jpg`：按帧排列的显示尺寸预览及清晰度指标。
- `report.json`：逐帧来源、尺寸、透明区域占比、边缘裁切、图集/网页镜像一致性和清晰度数据。

也可指定输出目录：

```powershell
python console-v2/audit_action_clarity.py --output .qoder/action-clarity-review
```

此脚本只读取素材并写审查报告，不会修改 `assets/actions` 或前端素材。

## 如何判断

项目动作帧使用统一的 256×256 单元格；桌宠以 160×160 逻辑像素绘制，并在 2 倍中间画布上合成。审查脚本因此把每帧以 LANCZOS 缩放到 320×320，再计算 Laplacian 方差、梯度能量和高梯度像素比例。报告使用同一动作内的相对值标记复核候选，不能把不同姿势或不同动作的分数直接比较。

身体姿势、角色占画布比例、背面细节、浅色线条和透明边缘都会影响指标。候选必须查看接触表并与前后帧、源帧对照；数值低不等于模糊。全帧统一锐化会放大白发和衣裙的边缘光晕，因而不作为默认修复。

## 建议的修复顺序

1. 若源帧本身清楚，沿用现有动作构建器：一个动作批次采用一致缩放系数，等比适配到 256×256，再用 LANCZOS 缩放；重新生成图集和公开镜像。
2. 若单帧源图确实偏软，先从原始关键姿态或高分辨率绘图重新生成该帧，再重建整段图集；不要对已经缩小过的 PNG 反复放大。
3. 若仅插帧偏软，优先重建该段插帧并检查眼睫、发丝、手指等细线是否撕裂；只有视觉确认后才考虑局部锐化。
4. 修复后再次运行审查，查看接触表，并确认 PNG 帧、图集和前端 WebP 镜像一致、角色没有碰到单元格边缘。

当前全库基线：57 个动作、1,573 帧；动作帧、图集与前端镜像在可见像素上相符。已标记的 19 帧候选经过接触表复核后，大多是姿势与内容差异造成的低指标，没有发现可安全批量锐化的帧。因此本轮保留正式动作素材不变。
