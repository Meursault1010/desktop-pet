# 前端 UI 美学：从 1000+ 真实界面提炼的安静秩序

> 研究语料：2,125 个候选页面（275 个真实产品/应用 + 1,850 个 Httpster 精选网站）；最终抽取 1,365 个目标，其中 **1,011 个页面**的 HTML/CSS 完成量化分析（成功率 74%）。另有 240 张人工研读的网站在屏截图，8 组联系表（software / minimal / typographic / dark / grid / colourful / commerce-fashion / editorial），以及 Linear、Raycast、Notion、Stripe 四个 live 产品参考。
> 方法：静态 HTML/CSS 量化抽取（字体、颜色、字号、圆角、间距、阴影、动效、断点、可访问性信号）+ 截图视觉研读 + live 页面观察。所有结论都经过三种证据交叉验证；量化数字描述的是“网页表层 CSS 的倾向”，不是对全部设计意图的完整还原。
> 适用：Web 应用、桌面应用界面、工作台、聊天、设置、内容站、作品集与营销页。它是一套判断系统，不是一套固定皮肤。

---

## 0. 一句话结论

**优秀界面之所以显得高级，不靠更多装饰，而靠更清楚的注意力秩序：一个焦点、一套字号、一种强调色、少量容器、处处一致的节奏，以及被认真对待的空白。**

风格会过时，秩序不会。任何“美学”，先是一套约束。

---

## 1. 十条原则

### 原则 1：先安排注意力，再选择风格

每个屏幕只允许一个主角。主角可以是一个数字、一句话、一张图、一个操作，或产品本身。其余元素按“支持、补充、可选”三级依次退后。

落地方法：
- 进入页面先问：用户第一眼应该看哪里？第二眼？如果答不出来，页面还没有设计。
- 使用“1 + 3 + N”结构：1 个主焦点，最多 3 个次级信息块，其余收进折叠或次级页面。
- 对比手段有优先级：尺寸 > 位置 > 明度 > 字重 > 颜色 > 装饰。不要用颜色去弥补层级失败。
- 删除不会改变决策的信息。仪表盘最常见的错误不是信息太少，而是所有信息一样重要。

反模式：每个卡片都有同样的标题、同样的边框、同样的阴影、同样的强调色——这等于没有层级。

### 原则 2：排版承担 80% 的设计

真实网站里，界面首先由文字构成。高级感大多来自字号跨度、字重控制、行高与字距，而不是插画和渐变。

落地方法：
- 建立 6–8 级的字号阶梯，而不是到处写 13px、15px、17px。推荐：11 / 12 / 13 / 14 / 16 / 20 / 24 / 32 / 40 / 56 / 72。
- 正文 14–16px；桌面工具类界面可 13.5–14px；营销正文 16–18px。
- 展示型标题要“大而紧”：字号越大，行高越小（0.95–1.15），字距越负（-0.02em ~ -0.04em）。
- 正文行高 1.5–1.7；中文正文 1.7–1.9 更从容。
- 小号全大写/等宽标签用于元信息（11px、+0.06em ~ +0.12em 字距），不要用于中文长句。
- 中文标题优先 600 字重，而不是 700/800；更细的笔画在屏幕上更显精致。
- 数字使用 `font-variant-numeric: tabular-nums`，时间、金额、计数器保持对齐。

量化倾向（全量语料）：
- 页面常用字号高度集中在 14 / 16 / 18px；最大/最小字号比中位数约 3.8 倍（p75 约 5.4）。展示型标题的最大字号有 44% 落在 48px 以上，其中 25% 超过 64px。
- 约 48% 的页面至少出现一处负字距，69% 出现紧行高（≤1.15）；它们集中在展示标题，而不是正文。
- 等宽字体出现在 59% 的页面中，常用于代码、ID、版本号、时间戳，是“工程感”的重要来源。

反模式：全站 13px；标题只比正文大 4px；所有文字同一字重；用彩色文字承担层级。

### 原则 3：中性色为底，强调色是信号而不是填充

成熟界面把 80–90% 的像素留给中性色，把颜色留给状态、主操作、品牌记忆点。强调色越多，注意力越碎。

落地方法：
- 先定义一条 9 级中性色阶（0/50/100/200/300/500/700/900），再定义一个强调色的 3 个色调（默认、hover、浅底）。
- 一个屏幕内，饱和色只出现在：主按钮、当前状态、关键数据、品牌标识。不要给每个图标上色。
- 背景使用“带一点色相的中性色”，而不是纯灰或高饱和蓝。冷色产品可用微蓝灰，内容产品可用微暖白。
- 深色模式不是把白色反相：用近黑（#0a0e12 ~ #121820）作画布，降低大面积饱和色，提高强调色明度，保留 1px 低对比分隔线。
- 文本对比度：正文 ≥ 4.5:1；大字号 ≥ 3:1；占位符也要可读，不要用 2:1 的灰。

量化倾向：
- 中性色 token 占比中位数约 0.64（p25 0.45，p75 0.83）；静态 CSS 还包含大量重置与框架色，视觉上的中性占比通常更高。
- 每页抽取到的强调色 token 中位数为 8 个，听起来很多；但视觉上通常收敛为 1 个主色加上成功/警告/错误语义色，其余是同一色的明暗变体。
- 以背景明度分类，约 40% 的页面偏亮、56% 为明暗混合或中间调、5% 偏暗；浅色背景高度集中在 #fff / #f8f9fa / #f7f7f5，深色背景集中在 #000–#111 与近黑蓝灰。

反模式：整套 UI 使用低饱和蓝灰；每个模块换一种颜色；用渐变填充所有卡片；把品牌色当背景大面积铺满。

### 原则 4：留白优先，容器其次

边框和卡片是最容易被滥用的“设计”。当分组可以靠间距、对齐和分隔线完成时，不要加容器。

落地方法：
- 先只用留白分组；不够时加一条 1px 分隔线；仍不够时才加浅色底；最后才加边框和阴影。
- 卡片不是默认组件。只有“可独立操作/拖拽/重复的单元”才需要卡片。
- 页面外边距 ≥ 24px（桌面 32–48px）；区块间距 40–64px；卡片内边距 20–28px。
- 列表行高 56–64px；设置项不要做到 90px 以上，那是浪费。
- 让空白有方向：把内容压向一侧，保留不对称的呼吸区，比四边等距更有编辑感。

反模式：卡片套卡片；每个 section 一个边框；所有容器同样的圆角和阴影；页面四周各 12px 的“安全边距”。

### 原则 5：形状系统要少而一致

圆角、边框、阴影是界面的“材质”。材质不统一，再好的排版也会显得拼凑。

落地方法：
- 圆角只用 4–5 个值：4（小控件）/ 8–10（输入、按钮）/ 12–16（面板）/ 999（chip、头像）。同一层级的元素使用同一圆角。
- 阴影只保留两级：贴地阴影（0 1px 2px，透明度 4–6%）与浮层阴影（0 12–32px，负扩散，透明度 15–25%）。普通卡片不需要阴影。
- 边框颜色要低于文字对比度一个数量级；深色模式用“提亮”而不是“加深”来做分隔。
- 交互元素必须有 hover / active / focus-visible / disabled 四种状态；静态装饰不需要。

量化倾向：
- 最多页面把 0 圆角（36%）或 1–4px 圆角（18%）作为主导，其次是 5–8px（10%）；12–16px 更多用于面板与浮层，而不是全局默认。pill 出现在 50% 的页面中，多用于标签与 CTA。
- 只有 20% 的页面使用柔和阴影；73% 声明了某种阴影，但多数是硬边、低透明或单层贴地阴影。大量页面依靠平面色块与 1px 分隔线完成层级。
- 渐变出现在 68% 的页面，backdrop-filter 出现在 39%；它们常见于营销页与首屏，应用界面应节制使用。

反模式：卡片 24px 圆角、按钮 6px 圆角、输入框 2px 圆角；每张卡片都有 0 8px 24px 阴影；浅灰边框配浅灰背景。

### 原则 6：节奏来自网格，不是装饰

好的界面在去掉所有颜色后仍然好看，因为对齐与比例成立。

落地方法：
- 使用 4pt 或 8pt 间距网格；常用值 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96。
- 桌面内容宽度 1200–1440px；阅读型正文 640–760px；设置页 640–760px；聊天正文 680–760px。
- 断点按内容需要设置，而不是照抄设备：可从 600 / 768 / 1024 / 1280 / 1440 起步。优先使用 `clamp()` 与容器查询处理组件级响应。
- 使用 12 列网格，但不要为了填满而填满；允许 2/3 + 1/3、1/4 + 3/4 的不对称。
- 图标、文字、按钮共享同一条基线；图标尺寸与字号成组（14/16/18/20）。

量化倾向：
- 最常见断点集中在 768 / 1024 / 767 / 1280 / 640 / 600 / 1200px；中位数页面声明 6 个断点（p75 为 10 个）。767 与 768 几乎同频出现，说明大量站点仍沿用“平板/桌面”的经典分界。
- 8 / 16px 是最常见的间距值，其次是 10 / 20 / 12 / 24px；但严格满足 4pt 对齐（≥75% 的间距值能被 4 整除）的页面只有 20%，说明“设计系统”和“实际 CSS”之间仍有明显差距。
- `clamp()` 排版出现在 31% 的页面，sticky 56%，`dvh` 31%，容器查询 18%；这些现代布局能力正在普及，但还不是默认。

反模式：所有内容居中；每个模块宽度不同；图标大小随手写 17/19/23px；响应式只做“挤不下就换行”。

### 原则 7：图像是内容，不是背景

研究样本中令人印象深刻的页面，几乎都把图像当作版式的一部分：全出血、强裁切、固定比例、与文字形成节奏。

落地方法：
- 先定义图像的角色：主视觉、案例、产品截图、头像、纹理。不同角色不同比例与处理。
- 使用固定比例容器（16:9 / 4:3 / 1:1 / 3:4），避免布局抖动；为图片预留尺寸。
- 产品截图要真实、清晰、有上下文；不要用低分辨率 mockup 填满页面。
- 文字压在图上必须有可读性保障：暗色遮罩、局部渐变、文字阴影三者选一，不要侥幸。
- 图像风格统一：同一产品内的摄影色调、插画线条、截图边框保持一致。

反模式：每张卡配一张无关的 stock photo；图片拉伸变形；文字直接压在复杂图片上；用 emoji 代替图像系统。

### 原则 8：动效只解释变化

动效的任务是让状态变化可理解，而不是展示技术。

落地方法：
- 常用时长 150–250ms；大范围布局变化 250–350ms；入场不超过 400ms。
- 使用 ease-out（cubic-bezier(.16,1,.3,1) 或 (.22,1,.36,1)）；避免默认 `ease` 的平庸感，避免弹跳。
- 只动画 `transform` 与 `opacity`；不要动画 width/height/top/left。
- 每个动效都要回答：什么改变了？从哪里来？到哪里去？如果答不出来，删掉。
- 必须支持 `prefers-reduced-motion`；减少动态时保留状态切换，不保留装饰动画。
- 背景氛围动画（星光、粒子、渐变）默认低透明度、低速度，并能被“减少动态”关闭。

量化倾向：时长集中在 150 / 200 / 300ms，页面中位数 325ms（p75 400ms）；线性缓动出现在 50% 的页面，内置 `ease`（45%）与 `ease-in-out`（47%）各约一半，显式 `ease-out` 只有 33%；缓动仍是被忽视的品质细节。只有 38% 的页面声明了 reduced-motion，这正是一个可形成品质差异的机会。

反模式：所有元素入场飞入；hover 放大 1.2 倍；页面加载动画超过 1 秒；无限旋转的装饰。

### 原则 9：可访问性是美学的一部分

真正精致的界面，键盘用户、低视力用户和鼠标用户看到的是同一个设计。

落地方法：
- 语义结构：`main`、`nav`、`header`、`footer`、`h1–h3` 层级正确；每个页面一个 h1。
- 可见焦点：`focus-visible` 使用 2px 强调色 outline + 2–3px offset；不要 `outline: none`。
- 所有图标按钮有 `aria-label`；表单有 label；错误用 `role="alert"`；动态内容用 `aria-live`。
- 图片有 alt；装饰图 `alt=""`；图标与文字并排时图标 `aria-hidden`。
- 触控目标 ≥ 40×40px；相邻目标间距 ≥ 8px。
- 支持 200% 缩放与 320px 宽度；不要用固定高度裁切文字。
- 颜色不是唯一状态信号：同时使用文字、图标或形状。

量化倾向：`main` 地标覆盖 57%，focus-visible 44%，reduced-motion 38%，skip link 仅 21%，带 h1 的页面 64%。把这五点做好，产品会立刻显得更专业。

### 原则 10：品牌是一个可重复的瞬间

高级产品不靠到处放 logo，而靠一个反复出现、可被记住的“物质瞬间”：Linear 的光晕与等宽 ID，Raycast 的红色光束，Notion 的暖白与高亮胶囊，Stripe 的渐变带。

落地方法：
- 选择一个品牌母题：光、材质、形状、插画、摄影、字体处理。只选一个，重复它。
- 母题出现在高价值时刻：空状态、主视觉、加载、成功反馈。不要在每个按钮上重复。
- 品牌色只做信号；品牌字体只做标题；品牌图形只做焦点。
- 让产品在去掉 logo 后仍能被认出：版式、语气、动效节奏也是品牌。

反模式：Logo 墙式品牌；每个页面换一种插画风格；把“高级”理解为金色和衬线字。

```css
:root {
  /* 中性色：带 1–3% 色相的近白到近黑 */
  --n-0: #ffffff;
  --n-50: #f7f8f9;
  --n-100: #eef1f3;
  --n-200: #dfe5e9;
  --n-300: #c7d1d7;
  --n-500: #78868f;
  --n-700: #3d4a53;
  --n-900: #121920;

  /* 强调色：一个色相，三种用途 */
  --accent: #2f6f8f;
  --accent-hover: #255c77;
  --accent-soft: #e7f0f4;
  --on-accent: #ffffff;

  /* 语义色只用于状态 */
  --success: #2f7d5c;
  --warning: #9a6a1f;
  --danger: #b3453f;
}
```

规则：
- 背景、表面、边框全部来自中性色阶；强调色面积不超过屏幕的 5%。
- 深色模式不是反相，而是重新定义同一组语义 token。
- 语义色不与品牌强调色混用；成功/警告/错误各自有浅底版本。

## 3. 应用界面模式

### 3.1 工作台 / Dashboard

- 一个“英雄区”承载最重要的状态（时间、健康、当前任务），其余模块扁平排列。
- 侧栏只放导航与全局状态；不要放第二个仪表盘。
- 模块标题统一小号；让数值和内容成为视觉主体。
- 数据行使用等宽数字；单位弱化；不要让每个数字都不同颜色。
- 空状态用一句有语气的话 + 一个明确动作，不堆插画。
- 可定制布局时，编辑态要明显但克制：虚线/浅底/拖拽手柄，不要把所有卡片都抖动。

### 3.2 聊天 / Copilot

- 对话正文限制在 680–760px；用户消息右对齐、强调色浅底；助手消息可无气泡，用一条细线或小标签区分。
- composer 永远可见：布局用 `dvh` 计算高度，消息区内部滚动，composer 固定在面板底部。
- 空状态是品牌时刻：一张角色图、一句短诗、三个可点击的开场问题，已经足够。
- 附件、模型、连接状态放在 composer 附近的次级层，不打断对话。
- 流式生成时有明确的阶段文案与停止按钮；不要把“思考中”做成无限旋转的孤岛。

### 3.3 设置

- 最大宽度 640–760px；分组标题 + 细分隔线；行高 56–64px。
- 左侧标签 + 描述，右侧控件；描述 12px、muted，最多两行。
- 开关、滑块、输入框共享同一种焦点样式；保存反馈就近显示。
- 危险操作独立分组，使用危险色文字但不要整块红色背景。
- 主题选择器用真实色板预览，而不是三个文字选项。

### 3.4 资源库 / 画廊

- 搜索是第一条工具，筛选 chip 是第二条；计数靠右、弱化。
- 卡片以内容为主：图片固定比例、名称一行、元信息一行；最多两层文字。
- hover 只改变背景/边框/轻微位移（≤2px），不要放大内容。
- 选中状态用 1px 强调色 ring + 浅底，不要用大面积实色。
- 详情预览使用 sticky 面板；让用户在看列表时始终能看到预览。

### 3.5 营销 / 落地页

- 一个大标题、一个副标题、一个主 CTA、一个产品视觉，足以完成首屏。
- 字体尺度可以极端（72–120px），但正文必须回到 16–18px。
- 一个品牌母题贯穿全页；渐变/光晕服务于母题，不作为通用背景。
- 社会证明（logo、数据、评价）放在首屏之后，不要抢主叙事。
- 首屏之外每个 section 只回答一个问题。

## 4. 反模式清单

看到以下信号，说明界面正在用装饰代替设计：

1. 每个模块都有边框、圆角、阴影，层级仍然不清楚。
2. 页面使用 5 种以上强调色，却没有一种能指出“下一步”。
3. 正文 12–13px，标题 16px，靠加粗和颜色制造层级。

6. 卡片套卡片，滚动容器套滚动容器。

13. 表单错误只靠红色边框，没有文字说明。
14. 图片没有固定比例，加载时布局跳动。
15. 依赖 hover 才能发现的操作，在触屏上不可用。

## 7. 把理念转译为 yuki 工作台

### 7.1 设计命题

**“安静的雪原仪器”（Quiet Alpine Instrument）**：像一台被精心校准的观测仪器，而不是一张企业后台报表。冷、静、精确，但不冰冷；有雪的留白，也有陪伴的温度。

### 7.2 气质关键词

克制 / 清澈 / 编辑感 / 触感 / 安静 / 可信 / 一点诗意

### 7.3 视觉决策

- **画布**：浅色主题使用微冷近白，而非整片蓝灰；深色主题使用近黑蓝灰，而非饱和藏蓝。
- **强调色**：只保留一种“冰川蓝”，用于主操作、选中态、焦点与关键数据。其余状态用中性明度表达。
- **字体**：UI 用系统无衬线；展示标题 600 字重、负字距；诗句与品牌保留衬线斜体；数据与时间用等宽/tabular。
- **容器**：取消“每卡必框”。英雄区用一块柔和材质；次级模块用留白与 1px 分隔线；只有可交互单元使用浅底。
- **导航**：文字 + 图标，当前项用 2px 指示条与极浅底色，不再使用整块深色。
- **形状**：面板 16px、控件 10px、chip 999px；阴影只给浮层与 composer。
- **布局**：宽屏 12 栏、内容最大 1280px；紧凑窗口单列；侧栏 200–220px。
- **动效**：180–240ms ease-out；页面切换轻微上移淡入；星光低透明度；尊重 reduced-motion。
- **品牌母题**：一条极淡的“极光/冰晶”光晕，只出现在英雄区与空状态，不铺满全站。

### 7.4 页面转译

- **总览**：时间成为主视觉（56–64px），天气是次级数据，雪的形象在一侧安静出现；今日足迹与陪伴节奏变成两条编辑栏目，而不是两张同质卡片。
- **角色**：动作预览与动作库形成“仪器 + 标本”的关系；预览 sticky，动作网格紧凑、低噪音。
- **AI 助手**：对话是唯一主角；composer 始终在视口内；右侧只保留模型与连接的必要信息；空状态保留诗与三个开场问题。
- **工具**：专注计时器成为页面焦点；待办与剪贴板使用列表而不是卡片堆叠。
- **设置**：收窄到 720px；分组靠标题与分隔线；行高 64px；主题选择器用真实色板。

### 7.5 不可牺牲项

- 三套主题（雪白 / 银雾 / 星夜）与紧凑/宽屏布局。
- 所有现有功能、键盘操作、aria 标注、错误提示与数据持久化。
- 对比度、reduced-motion、focus-visible、skip-link。
- 不引入新依赖；不改变 IPC 与业务逻辑；不改动发布目录。
