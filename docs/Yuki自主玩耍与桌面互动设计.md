# Yuki 自主玩耍与桌面互动设计

日期：2026-10-23。性质：基于当前源码的功能设计，不是已实现功能说明。本次仅撰写文档，不修改桌宠行为、素材、设置或启动入口。

## 1. 希望她看起来怎样

Yuki 不是不停巡逻的巡逻机器人，而是住在桌面上的小伙伴。她大多数时候有自己的安静生活，偶尔发现附近一个有意思的图标，走过去看看，犹豫一下，靠着休息；兴致来了绕半圈，累了就在原地坐下。

趣味来自**动机、停顿、反应和记忆**，而不是动作数量和频繁切换。一次活动应该能被看懂：她为什么出发、在做什么、为什么停下。允许她放弃一个计划，也允许她什么都不做。

沿用用户已确认偏好：主要待机、少走路；所有自主位移都有对应走路或翻滚动画；翻滚只在翻身阶段移动；动作幅度克制；睡眠保持安静；用户交互立即优先。

### 2.1 当前巡逻如何发生

- 初始化后约45–80秒首次尝试；取消或结束后，一般延后80–170秒，受活动档位影响。正式挑选时还受作息中的步行系数影响。这些是尝试间隔，不保证到点必定行动。
- 优先处理到时正餐和零食。早餐07–09点、午餐12–14点、晚餐18–20点；成功完成才记录当天已吃。零食间隔20–40分钟，仅09–21点考虑。
- 闲暇任务会让位于已经到期的随机待机动作，因此用户可能长期只看到待机，巡逻机会不稳定。
- 附近图标候选取较近的三个再随机选；候选距离受速度与360px上限约束，要求同屏、路径包围区域露出桌面。选中候选后有65%机会走图标分支。
- 未走图标分支时，再有45%条件概率选择侧滚，否则尝试散步。不能把65%、45%直接当成所有时刻的实际行为占比。
- 图标依靠通常停留25–55秒，小睡70–140秒；普通散步目标大致横向70–180px、纵向±85px，行走阶段固定9秒超时。
- 行进或图标互动期间约每秒检查目标/路径，目标移动、消失或遮挡就取消。当前是保守的直达可见性判断，不是完整绕障寻路。
- 拖拽、物理、安静/暂停、聊天、音乐、弹出菜单、边缘附着等会阻止巡逻；取消时只应收回自己拥有的动作与图标互动。

### 2.2 当前不足与潜在冲突

1. **随机任务缺少故事。** 选了动作，不一定让人理解她在探索什么。
2. **调度机会不稳定。** 既有待机与巡逻分别计时，可能相互抢占或长期让位。
3. **重复缺少对象记忆。** 总去最近图标，容易形成机械往返。
4. **超时与距离不匹配。** 固定9秒不适合所有速度、路线和停顿。
5. **睡眠分散管理。** 巡逻直接播放 `sleep` 与正式 SleepCycle 不是同一种状态，后续应统一，避免小睡没有完整唤醒或被作息逻辑误判。
6. **已有偏好边界需澄清。** 用户曾要求只有手动拖到边沿/图标才吸附；目前源码却仍存在自主走到图标依靠分支。新设计用独立开关明确授权，不能把拖放吸附开关偷偷解释为自主攀附许可。

## 3. 总体结构：生活状态 + 小任务 + 唯一执行权

不需要让聊天大模型每秒决定她做什么。确定性的规则负责位置、状态和约束，带权随机负责变化；模型未来最多提供可校验的意图或短句。

分三层：

1. **生活层**：当前时段、精力、好奇心、疲劳与用户忙碌程度，生成活动倾向。
2. **任务层**：挑选一个可执行的小故事，包括目标、阶段、超时、冷却和退出姿势。
3. **执行层**：复用走路、动作播放器、接触姿势、遮罩和睡眠管理，处理每一帧。

任何时刻只有一个行为拥有位置控制权；动作播放和接触遮罩也要记录所有者。旧任务结束时不能停止新任务或用户刚点选的动作。

## 4. 优先级和打断规则

以下是拟建立的仲裁规则，不声称当前代码已有这张统一优先级表。

| 优先级 | 事件 | 处理 |
| --- | --- | --- |
| 最高 | 退出、隐藏、暂停、显示器消失、非法坐标 | 停止自主任务，清理归自己所有的资源 |
| 用户直接操作 | 拖拽、抛出、手动选动作、主动移动、菜单交互 | 下一次主循环让出控制，不强行播完收尾 |
| 主动交流 | 用户发消息、点击/摸头等互动 | 停止路线，原地回应；冷却后另选新任务 |
| 正式睡眠 | 到睡眠时段且满足入睡条件 | 不再派发玩耍；用已有睡眠系统完成衔接 |
| 已获执行权的音乐互动 | 音乐舞蹈及其休息阶段 | 自主玩耍不插入；熟睡时音乐不能反复强制唤醒 |
| 生活需求 | 正餐、短休息 | 等低优先级任务到安全切换点，不能截断物理或用户动作 |
| 自主小任务 | 图标探索、绕行、侧滚、观察 | 有上限、有冷却、可随时放弃 |
| 基础待机 | 站立、坐下、趴着、呼吸眨眼 | 默认归宿；无需不断挑一个新任务 |

具体规则：

- 单击后的害羞动作属于用户回应，先停自主路线，再保留既有点击效果。拖拽立即取消接触遮罩，避免人物被图标裁掉。
- 右键菜单出现期间不移动。菜单关闭后等待10–20秒，不立刻续跑。
- 主动聊天结束后等待30–60秒；拖拽后等待20–40秒。再次打断则重置等待。
- 不自动接着跑原来的半条路线。旧目标重新验证，下一次决策重新选择。
- 用户明确手动指定的附着不因“任务超时”被系统擅自解除。
- 正在抛出或碰撞时，睡眠只记录待进入意图，待物理稳定再入睡，不在空中切成睡姿。

## 5. 活动节奏：不把桌面变成游乐场

以下参数是建议初值，后续需实际观察调参，不是当前配置。

### 5.1 时间预算

- 默认档：滚动10分钟内，自主走动及有位移翻滚累计不超过60秒；连续行走原则上不超过12秒。
- 少动档：同一预算减半；活跃档最多90秒，不取消路径和打扰约束。
- 无位移的呼吸、眨眼和安静坐趴不计入移动预算。图标附近的静坐仍是安静陪伴，不必为了预算强制起身。
- 一次小故事通常20–90秒，其中多数时间是在观察或休息。结束后至少60–120秒再启动下一次故事。
- 最多连续两个故事，随后安静休息3–6分钟。随机动作仍可出现，但不再主动远行。
- 长时间挂机也不提高到“全桌面跑动”；连续两次没找到安全目标就安静等待30–60秒，逐步退避到最多2分钟。

### 5.2 用户在忙时

只使用必要的本机输入时间与窗口几何信息，不记录键盘内容或推断用户具体工作内容。

- 输入活跃、鼠标在目标附近：降低出发概率，避开鼠标周围约120逻辑像素；距离按人物大小修正。
- 鼠标静止不等于允许她靠过去抢鼠标。鼠标互动单独开关，默认不抢占拖动、不拦截实际指针。
- 专注/安静模式：关闭自主位移和主动气泡，保留原地细微待机。到点睡眠仍由睡眠系统管理；暂停则冻结自主推进。
- 全屏窗口覆盖桌面：不去被遮住的图标，不自动爬上应用正文或窗口边框。允许在现有安全位置安静待着；角落移动需单独允许，且必须能合法走到，不能瞬移。

### 5.3 轻量内在状态

精力与好奇心均为0–100的内部数值，不必显示成养成数值条。

- 精力随走路、翻滚缓慢下降，坐趴缓慢恢复，正式睡眠明显恢复。精力低于30时不发起绕行，低于15只选休息。
- 好奇心在安静清醒时缓慢增加，探索成功后下降；新图标位置变化只增加少量兴趣，不触发立即奔跑。
- 记录最近六个任务、最近访问图标和失败目标；不保存图标截图或文件内容。目标标识优先使用既有稳定ID，但需容忍桌面重排后ID失效。
- 这些值只改变倾向，不绕过“睡觉、暂停、路径不安全”等硬条件。重启不补演错过的故事。

## 6. 挑选目标：有偏好但不会钻牛角尖

### 6.1 硬过滤先于评分

图标必须满足：同一显示器、坐标有效、图标及预期接触区可见、有足够身体空间、路线安全、不在鼠标避让区、不在失败冷却中。未经验证的候选直接删除，不给高分目标开例外。

第一版活动范围为当前位置附近约1–2个身高，最大360逻辑像素；保持当前同屏原则。跨显示器探索后续单独设计。

不根据图标名称猜测文件内容、隐私或用户任务。所有图标都可以是“小墙、小遮挡、小地标”；能可靠读到文件夹类型时才叫文件夹，否则文案统一说“这个角落”。

### 6.2 可解释评分

将各项归一化为0–1：

`分数 = 0.30 × 距离便利 + 0.25 × 空间适配 + 0.20 × 新鲜度 + 0.15 × 休息适配 + 0.10 × 熟悉偏好`

先剔除不可执行目标，再在得分最高的三个中按权重抽取；不是每帧重选最高分。

- 同一图标互动后冷却5分钟；同一故事冷却8分钟。同一位置不立刻重复侧滚。
- 最近两个故事的类型不重复；候选太少时选择原地休息，不能为了多样性违反安全条件。
- 经常休息的一个地点可以成为“喜欢的小角落”，但熟悉偏好最多占10%，不能压倒距离和可见性。
- 图标移动或消失后清除它的接触缓存；不能记住旧坐标继续坐在空气上。

## 7. 建议的小故事库

“现有素材可做”只指具备动作基础，不代表整套故事已实现。需要新姿势时先做预览供用户确认，再生成或接入。

| 故事 | 行为链 | 趣味与克制 | 素材基础 |
| --- | --- | --- | --- |
| 看看这个小角落 | 看向目标1–2秒 → 小步走近 → 停下观察2–4秒 → 坐10–25秒 | 有时看完就走，不必每次都附着 | `curious`、走路、`sit-relaxed`；需核对curious当前帧效果 |
| 借我靠一下 | 找侧面接触点 → 走到接近点 → 小范围对齐 → 靠20–45秒 → 站起离开 | 先迟疑再放心靠上，头发轻轻落稳 | 现有左右依靠姿势；离靠过渡可能需补帧 |
| 这里可以藏一点点 | 走到图标侧后方 → 探身停一下 → 身体部分遮挡 → 看向用户 → 自己出来 | 不整个人消失，不模拟关闭宠物 | 遮罩基础已有；探头关键姿势可能需新增 |
| 只绕半圈 | 找两到三个安全路点 → 走一小段 → 停住看看 → 换方向离开 | 不固定转圈；半途发现无路就放弃 | 走路已有；不靠横向缩放伪造背身 |
| 在这里晃晃腿 | 确认顶面能提供视觉支撑 → 走近 → 坐上 → 轻晃腿15–35秒 → 回到地面 | 只适合接触几何与人物比例合适的图标 | 顶部坐姿已有，稳定接触点与上下过渡需验证 |
| 翻个身就歇着 | 找空白区 → 趴下 → 一次慵懒侧滚 → 趴着15–35秒 | 翻身关键帧才位移，侧躺停帧不漂移；不连翻数圈 | `lazy-roll-toward/away`、`prone-rest` |
| 找个位置读一会儿 | 找靠近图标但不压文字的位置 → 坐下 → 阅读20–50秒 → 合书/抬头 → 待机 | 可只是安静待着，不需要每次说话 | `reading-pose-1/2`、`read`；进出姿态需核对 |
| 下午的小茶歇 | 站坐待机 → 伸懒腰 → 喝茶 → 安静观察 | 不强制移动到图标，保留生活感 | `stretch`、`tea` |
| 玩累了 | 从当前姿势收势 → 坐下或趴着 → 呼吸休息 | 是前一个故事的自然后果，不独立高频抽取 | 坐趴待机已有 |

### 图标下睡觉如何处理

只在正式午睡/夜间睡眠允许的情况下选择安全休息点；找不到目标就原地入睡。不得为了找图标拖延睡眠超过10秒。

白天非睡眠时段的“困了”先做打哈欠、趴着闭目休息，不额外引入另一套长睡眠状态。若以后确实要白天自由小睡，应扩展 SleepCycle 的显式短睡请求，并沿用同一套唤醒、禁言、zzz和两分钟规则，不由 Patrol 私自循环 `sleep`。

保持已确认的统一枕头与缓慢漂浮、无边框的可爱zzz；不能恢复已删除的旧“靠文件夹睡觉”动作。图标附近休息可复用现行认可睡姿与位置遮挡。

### 一次完整体验示例

14:35，她已经安静待了两分钟。附近一个图标侧面露着桌面，鼠标在另一边。她看过去，走三秒，停一秒，轻轻靠着待25秒。途中没有气泡。离开时整理一下头发，回到坐姿。接下来至少一分钟不再出发。

16:10，她想绕一个图标走走。走到第一个路点时，一个窗口盖过来。她停止前进，放弃原计划，原地站稳；如果当前位置也被覆盖，就不继续做“在桌面探索”的戏。之后降低重试频率，不穿过窗口去找目标。

21:20，她的活动倾向降低。即使好奇心很高，也只选原地梳头、打哈欠或在近处坐下，不长距离奔走。00:00进入正式睡眠，不再抽取故事。

## 8. 统一任务状态机

`休息 → 观察 → 规划 → 行走 → 接触准备 → 执行 → 收势 → 冷却 → 休息`

任何阶段都允许转向“打断/目标失效”，再交给新的高优先级行为；不是所有任务必须走完所有阶段。原地侧滚跳过寻路，普通观察跳过附着。

| 阶段 | 进入条件 | 结束/失败条件 |
| --- | --- | --- |
| 观察 | 获得低优先级执行权，有可用预算 | 1–2秒；用户移动到目标附近则放弃 |
| 规划 | 当前桌面快照有效 | 找到路线；否则失败冷却 |
| 行走 | 目标有效、路线安全、非附着姿势 | 到达接近点；超时/路径失效则停止 |
| 接触准备 | 支撑点、人物比例和接触姿势有效 | 站稳并完成姿态衔接；几何不适配则退化为旁边坐 |
| 执行 | 当前任务拥有动作控制权 | 阶段时长结束、条件改变或用户打断 |
| 收势 | 无高优先级请求，离开姿势可用 | 交还正确的站/坐/趴姿态，不强制闪回站姿 |
| 冷却 | 已完成或安全放弃 | 计时结束后才允许下一次决策 |

### 防止互相抢动作

每个任务分配唯一 `task_id` 和递增 `generation`。异步扫描、路点结果和播放结束回调都携带它；结果回来时不匹配就丢弃。

位置、动作、遮罩分别记录 owner。取消只释放自己的资源；“播放时刻相同”不再作为唯一所有权标识。与用户手动动作并发时，以用户动作的代次为准。

在基础待机出现可中断点时发放一个低优先级机会，由统一仲裁选择“继续待机”或“小故事”；不让两个独立计时器互相无限让位。候选冷却到期只是获得资格，不是强制抢动作。

## 9. 移动、接触与遮挡的几何规则

### 9.1 先让短路线可靠，再做复杂寻路

第一版沿用保守同屏直达检测：附近没有安全路径就不去。不要把当前路径包围矩形检测包装成真正的导航网格。

第二版可加入低分辨率占用网格或少量路点：对窗口障碍按人物可见身体范围膨胀，在安全网格上寻路，再做路线简化。应实测检测成本，优先增加一两个转折点，不做全桌面实时重建。

目标图标是允许靠近的互动对象，其他图标的图像与名称区作为软避让区；窗口正文、任务栏和屏幕外侧是禁止区。图标是平面视觉地标，不宣称具有真实三维碰撞体。

### 9.2 路径验证与超时

- 候选扫描建议闲暇每15–30秒，活跃目标每0.5–1秒确认；拖动窗口等几何变化可使计划立即失效，但必须节流。不能每帧枚举所有桌面窗口。
- 运动前检查下一小段路径，较低频率验证整条路线；检测失效或不确定即停止，不将失败视为“无遮挡”。
- 行走超时根据 `路线长度 / 实际速度 × 1.5 + 2秒` 计算，再限制最大连续行走12秒；超预算应在规划阶段缩短路线或拒绝。
- 自主移动用单调时钟和dt，作息用本地墙钟。电脑休眠后丢弃旧路线，不能把长dt累积成瞬移。
- 一次任务最多重新规划一次；再次失效就休息，不循环追着移动图标跑。

### 9.3 到达不是瞬移吸附

先用接触姿势计算最终支撑点，再倒推出走路接近点。进入最后几像素后减速、站稳、切换对应姿势，不能走到另一处再调用 `instant=True` 明显跳过去。

拖放即时吸附仍保留原来“松手即贴合”的体验；它与自主走近的衔接策略不同。调整窗口位置只是表现接触，不应该改动真实图标坐标。

依靠和坐姿使用身体锚点、脚底/臀部/手部接触点及透明边界，不仅按PNG画布中心对齐。顶面空间不足，改旁边坐；遮罩不可靠，改不遮挡的互动。失去支撑后先取消对应遮罩和接触状态，再播放已有恢复姿态，不保留半个人物。

## 10. 动作连续性与素材计划

### 10.1 先处理结构，再考虑插帧

将动作标记为站、坐、趴、依靠、顶部坐等姿态，并定义可用的进出衔接。只有姿态兼容的动作才直接相接。

- 站立→走路：从支撑脚开始，短距离加速，位移与步频对应。
- 走路→坐下：减速落脚，再坐下，不边走边切静态坐姿。
- 坐→趴：有认可桥接才播放，否则先起身再趴；无素材就选择当前姿态能做的任务。
- 侧滚：复用当前分帧位移曲线及既有方向映射，不能重新假定朝屏幕滚就是水平移动。先做预览确认方向，静态侧躺阶段位移为零。
- 依靠→离开：从接触处卸力、收势再迈步，避免画面突然回正。
- 收尾可以留在坐/趴基础呼吸，不需要每个故事结束都站起来。

减少重影优先级：锚点和尺寸一致 → 正确桥接帧 → 合理帧时长 → 局部程序微动。不同轮廓的大幅姿态不要靠长时间透明叠加解决。

### 10.2 分批素材需求

第一批优先复用现有走路、坐趴、阅读、茶、梳头、伸懒腰、左右依靠和慵懒侧滚。先把节奏、打断和接触点调好。

第二批只补必要桥接：走路停稳、依靠进入/离开、图标顶面坐下/下来、半遮挡探头。新图先审核，不在本设计阶段自动生成。

Live2D 可以增强局部呼吸、视线和接触后的细微晃动，但不是实现任务调度或路径规划的前置条件，也不假定项目已经具备可用Live2D模型。

## 11. 文案和状态可解释性

- 一般每个故事不说话；建议只有10%–15%故事结束时出现一句，且自主气泡至少间隔3分钟。睡眠、专注、聊天中不插话。
- 短句描述她自己：“这里刚好可以靠一下。”“只翻一次……再躺一会儿。”不假装知道文件内容，不说“我帮你整理好了”。
- 工作台行为逻辑页沿用现有风格，显示：**现在在做什么、当前目标、下一步意图、暂不行动的原因**。
- 例如：“正在走向附近图标 / 到达后可能坐一会儿 / 路径安全”。未来意图是暂定，不提供虚假的精确倒计时。
- 被阻止时显示“专注模式中，原地休息”“桌面被窗口遮住，暂不探索”“刚被拖动，先陪你一会儿”，而非始终写“正在巡逻”。

## 12. 设置与已有偏好的边界

建议只增加一个主开关和少量展开设置，复用角色→行为逻辑页面，不增加一级栏目。

| 设置 | 建议行为 |
| --- | --- |
| 自主玩耍 | 用户主动启用；旧设置迁移保留原值，不静默开启新的互动能力 |
| 活跃程度 | 沿用少动/默认/活跃，调整预算和等待，不突破硬约束 |
| 自主与图标互动 | 独立许可；关闭时仍可在安全空白区散步和原地活动 |
| 拖放即时吸附 | 沿用当前开关，只控制拖放行为，不捆绑自主图标互动 |
| 自主窗口边框互动 | 第一版不包含；沿用手动拖放/已授权的物理攀附，不因本设计扩大范围 |
| 自主短句 | 可关闭；不影响用户主动聊天 |

优先尊重“主要待机、少走路”；“随意走动”理解为不固定机械路线，而不是不限距离、次数或区域。

## 13. 失败与边界情形

| 情况 | 处理 |
| --- | --- |
| 桌面没有图标、扫描失败、Explorer重启 | 清除失效候选，短暂退避；退回原地待机，不持续弹错误气泡 |
| 图标被移动、重命名、删除 | 重新确认身份和坐标；移动失效一次重规划，删除直接放弃；重命名不代表文件内容变化 |
| 窗口盖住目标 | 不继续走入窗口；停下并撤销任务，不瞬移出覆盖区域 |
| 人物被用户放在屏幕边缘 | 只生成不出界的候选；没有空间就原地休息 |
| 多屏、负坐标、不同DPI | 用统一Qt逻辑坐标；扫描结果通过现有转换入口适配；第一版不跨屏 |
| 改变人物大小或显示器缩放 | 废弃接触点、路线和旧遮罩，重新计算，不复用旧像素偏移 |
| 到睡觉/吃饭时仍在玩 | 睡眠按仲裁收尾进入；正餐等安全切换点，错过窗口不连吃多顿补演 |
| 用户反复点击、拖动 | 持续以用户为主，冷却重置；不能通过累计任务队列稍后集中播放 |
| 重启、休眠恢复、系统时间改变 | 清除当前路线与瞬态控制权；餐食沿用现有日期记录；按当前本地时间重新判断作息 |
| 素材缺失或接触点无效 | 删除该候选故事，退回可用待机；不显示透明人物或占位图 |

## 14. 分阶段落地计划

### 第一阶段：先把调度与退让做好

为 Patrol 增加任务ID、统一机会仲裁、冷却/预算和明确取消原因；保留现有动作与同屏保守路径。把图标短睡交给统一睡眠规则，拆开自主互动与拖放吸附许可。先实现“走近看看、靠一下、滚完歇着”三个故事。

### 第二阶段：动作和接触自然

建立姿态进出表、接触锚点和进出过渡，去掉自主到达后的明显位置跳变。再加入坐着阅读、晃腿和必要的桥接素材。

### 第三阶段：有一点自己的偏好

加入轻量精力、好奇心、目标冷却与熟悉角落。增加可选短句和行为说明，但不把数值系统做成需要用户照料的负担。

### 第四阶段：可选的复杂路线

在基础稳定后考虑少量绕行路点、探头躲藏和安全网格；跨屏与自主窗口攀爬另立设计。聊天模型可以提出“我想去休息”这样的意图，但不能提供任意屏幕坐标或直接执行桌面操作。

主要改动位置：`pet_patrol.py`、现有行为仲裁/位移入口、`icon_sleep.py`接触逻辑、待机和睡眠接口；前端仅扩展行为状态、少量设置与IPC。不要在 Electron 再加一套位置控制循环。

## 15. 验收标准

1. 连续观察清醒默认模式30分钟：看得到至少两种可执行故事，但不保证固定时刻出场；移动时间满足滚动预算，多数时间安静待机。
2. 固定随机种子与假时钟验证选择、冷却、精力和超时；以可见动作验收故事，不仅核对状态字段。
3. 拖拽在下一次主循环接管位置；目标响应在正常主循环下约一帧，不作所有设备固定毫秒数承诺。旧异步结果不能复活任务。
4. 打开菜单、发送消息、切专注、手动选动作后，不再继续旧路线，不抢用户动作，不残留接触遮罩。
5. 图标消失、被窗口遮挡或尺寸/DPI改变后，不穿行、不追逐旧坐标、不无限重规划。
6. 侧滚方向继承已确认映射；停留帧位置不变，翻身阶段平滑位移，结束处能自然趴着。
7. 熟睡期间不派发故事、不自主说话；按已确认条件唤醒，安静两分钟再入睡。
8. 无图标、无路径、缺素材时都能继续正常待机。不能为了凑“趣味性”强制播放失败动作。
9. 开关独立：禁用自主图标互动不影响拖放吸附；禁用拖放吸附也不代表获得自主互动授权。
10. 实际验证高DPI、多屏负坐标、桌面被全屏覆盖、Explorer重启与休眠恢复；记录路径探测耗时和主循环帧时间，确认扫描不阻塞拖拽。

这套方案的核心体验是：**她偶尔有一件想做的小事，完成或放弃后，又自然回到你的身边。**
