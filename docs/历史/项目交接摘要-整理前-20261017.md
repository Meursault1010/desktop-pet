## 4. 已完成工作

### 控制台与通信

React 19、TypeScript、Vite 7、Tauri 2；使用 Radix 控件和 Lucide 图标。已有总览、外观、行为、互动、设置、动作库、依靠睡眠页面，浅深主题、数值输入与滑块、错误反馈、连接和保存状态。

通信链路是 React → Tauri invoke → Rust → Python stdin/stdout 逐行 UTF-8 JSON，没有 HTTP 服务或开放端口。Python 是状态来源；请求有编号、响应与推送含状态快照，前端用 revision 丢弃旧状态。命令排队、合并未发送的同项偏好，避免切页丢失滑块最后一次修改。重复等待中的动作去重，动作超时不自动重发。Rust 使用命令白名单；Python 再校验参数，不能由前端任意指定文件路径。

Python 输入线程仅投递消息，Qt 主线程修改窗口。stdout 只能输出协议，日志写 stderr。后端退出提示断线，可重新连接；管道关闭时后端退出。新版托盘由 Tauri 管理，不创建第二套 Python 托盘。重复启动新版唤起已有控制台。关闭窗口不等于退出，通常隐藏到托盘；无托盘时最小化。

保留大小、不透明度、置顶、速度、活动频率、随机走动、暂停、安静模式、问候气泡、拖动、跳跃、回到底部、隐藏与恢复默认。设置通常存于 `%LOCALAPPDATA%\XiaoJu\DesktopPet\settings.ini`；主题在 WebView 本地存储，不能通过替换程序重置用户偏好。

### 连续待机与闪烁修复

角色已从早期外观替换为用户白发蓝裙素材。默认待机不是“隔几秒播放一下”：可见时持续约 30fps 刷新，呼吸与头发运动连续，脚底稳定；随机眨眼独立计时，约 2.8～6.8 秒，20% 概率双眨。暂停走动、安静模式不停止呼吸；隐藏才停止刷新。当前是图片局部柔性变形与相位图集，不是完整 Live2D 模型。

`prepare_living_idle.py` 预生成 64 个连续运动相位及睁眼/半闭眼/闭眼三套图集。Qt 在相邻相位间做预乘 alpha 插值。曾经的闪烁不能简单归因于缺帧或素材亮度：Qt Plus 配合 painter opacity 没有按预期得到稳定加权和，且快速路径有 alpha 精度损失。当前使用浮点预乘 RGBA 表面，以 DestinationIn 高精度权重遮罩分别加权，再在完整不透明度下 Plus 相加。不要退回两次 setOpacity 绘制或普通 SourceOver 叠加。

### 动作库与电子屏幕修订

现有 31 个目录项，包含已有素材转换、新增六关键帧动作和 3 个单帧阅读姿势；不是 31 个高帧率完整动画。新增动作覆盖伸懒腰、跳跃、微笑、害羞、生气、沮丧、等待、工作、喝茶、打哈欠、查看文件、庆祝、梳头、整理衣服、撒娇、好奇、害怕、点击和拖动反应等。

动作库支持搜索、分类、播放暂停、0.25～2 倍速度、循环、逐帧时间轴、在桌面播放和恢复待机。预览与桌面播放相互独立。动作表通过静态 import 打包到控制台；资源修改后必须同步 `frontend/public/actions/` 并重编 EXE。曾出现“动作库空白/加载失败”，继续维护时重点检查 catalog 打包、资源路径及 EXE 是否过旧，不要只检查 Python。

`screen` 口袋电子屏幕动作已重做为 12 帧：从口袋取出一次，屏幕始终握在手中，光照脸部并操作；`loop_start=5`（零基索引）使后续只循环持屏操作段，不重复取出。前端与 Python 必须使用同一循环语义。播放大幅动作直接按帧时序切换，不用整图透明交叉淡化掩盖缺少中间帧。

### 依靠真实桌面图标睡眠：最终规则

用户最新要求覆盖之前“保护所有图标/保护文字/正面遮一半”等方案：**只有依靠的目标图标能遮挡裙摆，头发始终前景；其他图标不裁切宠物；所有文字不裁切宠物，宠物可以遮住文字。** 不要回退旧规则。

已有自动、左侧背靠、右侧背靠、背对屏幕、正面背靠四种姿态。按肩背接触点定位，不按脚底对齐。用户要自然人的背部/侧背依靠，不是脸贴图标。默认自动侧面或背面，正面可手动选。

Windows Shell 的 IFolderView2、IShellFolder、IAccessible 只读获取真实图标边界与带 alpha 位图，不移动、打开或删除文件。后台扫描不放进每帧绘图。原生物理坐标转换为 Qt 逻辑坐标，已做当前机器 150% 缩放检查。

实现不是把宠物整个窗口塞进 Explorer 后面，也不是画一个假的文件图标：宠物保持普通透明窗口，通过 `setMask(QRegion)` 挖掉“目标图标 alpha 轮廓 ∩ 裙摆遮罩”的交集，让下面真实 Explorer 图标露出。只有挖空区域能直接操作底下图标，头发与文字处仍可点击宠物。遮罩每帧跟随睡眠呼吸的 `pose_rect()` 同步变换。

当前裙摆遮罩是针对白发蓝裙素材的保守规则：图像高度 62% 以下、alpha 非零、蓝通道大于 80、红小于蓝的 0.70 且蓝减红大于 40；因此白发不被误切，但浅色裙边可能仍在前景。它不是通用语义分割，更换服装或发色需重做，不能承诺所有裙子像素都会被挡。

已修复普通应用窗口交叠导致整只宠物消失，以及周围图标密集就拒绝依靠的问题。目标图标位图未加载时完整显示宠物，不挖矩形洞。屏幕边缘按真实 alpha 轮廓和全呼吸周期包络计算，优先自动换不出屏的姿势，即使用户选了固定方向也优先完整显示；仍放不下则最小内移，不因透明画布空白拒绝。仅角色本身大于可用区时提示缩小。

可控参数：水平/垂直偏移 ±100 Qt 逻辑像素、呼吸 0～100%（默认 55）、时长 0～120 分钟（0 为持续）、拖动松手自动依靠开关（默认关）、距离 30～240（默认 100）。保存在原配置 `icon_sleep` 分组，不自动恢复上次目标。点击、拖动、手动动作、跳跃、隐藏、回到底部、改变大小/置顶/显示器布局会醒来；目标移动/删除/改名或桌面不可用也醒来。安静模式不打断睡眠呼吸。

## 5. 生图到动作的实践流程

1. 先清点已有静帧和运行目录，确认哪些已经成动作；复用原素材，不反复付费生成。
2. 对照参考图与三视图固定脸、发型、衣服、配饰、比例、视角、画布、光照、相机和脚底/接触锚点。先设计动作关键姿势、道具连续性和循环接缝，再写提示词。
3. 需要生成或编辑时，先读取当前可用的生图技能说明；此前使用 shengtu-skill。用户允许必要时自行生图和评估，但仍遵守当前权限与技能要求，不假设历史技能配置永远有效。
4. 原始生成图、完整 prompt、修图版本保留在 `action-work/<动作ID>/`。API 密钥由技能私有配置获取，禁止复制到项目、输出到日志或写入交接文档。
5. 六格图拆帧后去背景、清理边缘、统一透明画布与角色尺度，校准锚点和亮度。不要误把生成的棋盘格当真透明，也不要把包含多角色总览的图当单帧。
6. 输出 `01.png...`、`atlas.png`、`poster.png` 和 catalog 的帧时长/列数/循环段等。运行时主要是 PySide6，不应新增 Pillow/OpenCV 运行依赖。
7. 检查浅色与深色背景接触表、GIF、前端预览及真实桌面：观察脸/服装一致性、道具是否消失、发丝抖动、轮廓跳变、脚底漂移和循环接缝。大动作缺中间帧要定向补画，不靠复制帧或整图淡化冒充流畅。
8. 前端与后端资源同步后构建、测试；用户退出后备份、部署、校验文件哈希，并在实际桌面项目再跑回归。

## 6. 已知问题与非目标

- 当前 EXE 仅控制台，依赖项目源码、assets 和 `.venv`；还未制作 Python sidecar 独立安装包、签名和安装器。
- 当前连续待机是程序变形，不是完整骨骼绑定；移动没有专门走路素材。睡眠靠近是平滑平移，尚无转身坐下、起身和绕障碍动画。
- 依靠分层只处理选中的真实桌面图标，不实现普通应用窗口对宠物身体的局部遮挡；沿用用户的置顶偏好。
- 目标在肩背位置时，未必与裙摆相交，因此某些姿势看不到明显遮裙是几何关系所致，不一定是程序失效。需要真桌面验证位置是否符合用户视觉预期。
- 睡眠裙摆遮罩保守，浅色花边可能露在图标前；更精确需求应制作人工部位蒙版，而非不断放宽蓝色阈值误伤头发。
- 动作库旧 `folder-sleep` 仍标记待精修，和真正依靠桌面图标的 `icon_sleep.py` 功能不是同一个东西。单帧阅读姿势不能称完整动作；六关键帧仍可能线稿漂移。
- 混合 DPI、多显示器、不同桌面图标大小、主题和真实点击穿透仍需要实机验收。离屏截图不等同 Windows 最终窗口合成。
- 控制台概览角色预览不是桌面画面的实时录像；不要把预览静态误判为桌面动画未运行。
- 未实现 AI 聊天、语音、开机启动、全局快捷键、皮肤导入、在线服务；这些是后续选项，不是已经承诺完成。
