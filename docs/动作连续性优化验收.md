# Yuki 动作连续性优化验收

日期：2026-10-19。用户已确认坐下与慵懒侧滚对比预览，并授权接入正式启动版。

## 已交付

- 保持 Electron 工作台与 PySide6 透明桌宠架构。
- 姿势之间使用离线双向光流形变，每段保留 25 帧，与确认预览的采样密度一致。每个画面只取一个形变后的角色，不通过双人物叠化补帧。
- 266 段候选中，256 段通过时间跳变与轮廓面积筛选；10 段继续使用原素材，避免大幅拉伸。原始动作图集不覆盖。
- 播放器按实际时间采样并缓动。长停留先保持安静，只在时段末尾转入下一姿势；绘制采用 16ms 精确定时器。
- 坐趴微动作保持随机间隔，并回到稳定姿势；侧滚维持完整角度顺序，加入现有趴下准备姿势。
- 局部呼吸与发梢跟随保持连续相位；侧滚及飞行、碰撞不额外套用呼吸形变。拖拽、物理与人工交互继续优先。
- 贴图后台解码，绘制时不等待磁盘；贴图与解码缓存有数量上限。

## 正式启动位置

根目录 `start.bat` 调用 `start-electron.bat`，优先启动：

`releases/electron/yuki-win32-x64-continuity/yuki-win32-x64/yuki.exe`

最终素材已同步到可读素材目录及冻结后端的 `_internal/assets/action-motion`。256 个图集的两份发布副本共核对 512 次 SHA256，均与源码素材一致。25 帧图集总计约 345MiB；为保留已确认效果，没有采用降低为 7 帧的体积压缩方案。

当前运行的旧版实例没有被强制结束。请先在旧版中“保存并退出”，再双击根目录 `start.bat`，以加载新包。

## 边界与维护记录

这次是现有 PNG 的局部形变与程序过渡，不是新建 Live2D 模型。较大的遮挡与身体转面仍受原素材限制，10 段未通过筛选的转场没有强行补帧。后续要进一步改善这些段落，需要补画关键姿态或制作分层多视角模型。

补充运行历史 `test_action_scale` 时，4 项中有 2 项通过、1 项失败、1 项错误：旧尺度报告缺少后来加入的 `actions/throw-flight` 记录；站姿高度规则应用到 `impact-left` 时，差值为 21 像素，超过原测试的 19 像素阈值。本轮未修改投掷、碰撞原图，也没有把这套历史尺度检查记为通过。应在后续尺度维护中补齐物理动作记录，并为非站立姿势使用适合的基准。

离线重新生成素材需要 `requirements-motion.txt` 中的 OpenCV 与 Pillow；桌宠运行不依赖 Pillow。运行 `build_action_inbetweens.py` 后，应先完成生成再验证或复制发布，避免读取到更新中的图集和旧清单。
