# yuki 动作衔接与 Live2D 分工

更新：2026-10-18。本轮仍运行 Electron 工作台与 PySide6 PNG 桌宠，没有加载 Live2D SDK 或模型。

## 本轮优化

此前跨动作淡化约 220 毫秒，部分关键帧间又淡化 80 毫秒。站立与趴卧、头部不同角度、伸出的四肢会同时出现。延长淡化不能补出中间姿势，只会延长重影。

现在比较切换前后缩略轮廓及颜色：轮廓高度接近的小变化，最多用 55 毫秒交接；大幅变姿、走路和飞行直接显示单一姿势。坐趴和侧滚内部按原绘制帧播放，不再叠加两个人物。缓存保存未混合的原帧，连续切换不会把旧残影继续带入下一次。

坐趴保留入姿、随机小动作与完整收姿；细节间回到稳定姿势。眨眼前的半闭眼缩短停留，避免长期半闭。侧滚保留方向和角度顺序，减少转动中的长时间停顿，首尾仍会懒懒地歇一会儿。

所有速度以素材目录中的毫秒时长为基准，动作库与原生桌宠共享同一份数值。1× 是推荐速度；用户仍可手动倍速。阅读、茶、等待偏慢，梳头、整理衣服居中，受惊、点击、跳跃反馈偏快。音乐互动仍允许有限的节拍调速。走路继续按实际位移推进步态，不按统一倍速修改。

PNG 仍有帧数上限：大幅姿态间可能看得出切帧。取消双影不等于产生了真实中间帧；缺少的解剖变化需要补画或模型，不使用整张图片缩放假装肢体运动。站立呼吸图集相邻帧原本差异很小，保留原有高精度短帧插值，避免破坏连续呼吸。

## 技术分工

| 动作或效果 | 推荐方案 | 原因与交付要求 |
| --- | --- | --- |
| 呼吸、眨眼、视线跟鼠标、转头 | 优先 Live2D | 连续参数比逐帧切换自然；提供眼球 XY、左右眨眼、头 XYZ、呼吸参数。 |
| 害羞、微笑、受惊、摸头反馈 | 优先 Live2D | 面部可连续变化，叠加身体动作；准备表情文件与参数优先级。 |
| 拖拽时看向抓取点、短胳膊努力够不到 | 优先 Live2D | 需要眼、头、肩、手臂独立形变；用抓取点驱动，有解剖范围限制，不能拉长整条胳膊。 |
| 猫耳、长发、裙摆的惯性和碰撞后余振 | 优先 Live2D 物理 | 分层网格和物理组，限制摆幅，避免穿模。 |
| 轻晃、音乐舞步、伸懒腰、挥手 | Live2D 增强 | 做可循环动作与自然收势；节拍仅驱动有限参数，站稳后再淡出动作权重。 |
| 阅读、喝茶、梳头、进食、整理衣服 | PNG 先优化，之后按需 Live2D | PNG 的道具与轮廓已完整。Live2D 需要道具分层、手部姿势和遮挡切换，不能只靠一张立绘变形。 |
| 完整侧向翻滚、前后侧背面切换 | 保留 PNG 或单独多视角模型 | 发生真实遮挡变化，普通正面 Live2D 无法自动生成后脑和背面。优先补连续中间帧，保持头脚方向。 |
| 坐下、趴下、起身 | PNG 完整姿态链；高质量模型可替换 | 大变姿需要专门绘制与绑定，普通半身模型不够。多姿态模型应有共同锚点和入出动作。 |
| 抓窗边、悬挂、爬行、图标依靠 | PNG 接触点先校准，Live2D 做局部细节 | 手/臀/身体接触点必须稳定，不能因物理摆动滑出边框。 |
| 走路、抛掷、重力、碰撞、即时吸附 | 继续代码控制位置 | 模型负责姿态，桌面物理与碰撞属于位置系统，不能迁入模型后失效。 |
| 果冻弹性、出现消失、星光、气泡 | 继续程序动画 | 已有代码可连续插值；Live2D 只增强身体部位响应。 |

这里的“优先 Live2D”是质量和后续制作选择，不是这些动作只能用 Live2D 实现。现有 PNG 继续作可用回退。

## 给 Cubism 制作的交付清单

- 全身分层源画：头发前后层、猫耳、脸、左右眼白/虹膜/眼皮、眉、嘴、躯干、左右上臂/前臂/手、裙摆、腿与鞋；道具分层。隐藏区域补全，保持现有头身比例和发夹方向。
- 可运行导出：`.model3.json`、`.moc3`、纹理目录、`.physics3.json`、`.exp3.json` 与 `.motion3.json`。`.cmo3` 是编辑源文件，不能直接在桌宠中运行。
- 明确中立姿态、模型逻辑尺寸、脚底/臀部/抓握点锚点；多姿态共用同一屏幕尺度。准备 `idle`、`enter`、`exit`、`loop` 与受打断时的恢复姿势。
- 推荐首批：站姿呼吸与眨眼、鼠标视线、害羞/摸头、拖拽够手、轻晃/挥手；随后再做道具和坐趴。侧滚最后处理，不强行扭正面模型。

## 接入顺序与边界

现有 Electron 原型已有 `PetRenderer` 接口，但生产透明桌宠仍是 PySide6，不能仅添加一个 TypeScript 类就完成替换。后续先单独验证 Electron 透明窗口、点击穿透、DPI 和多屏，再接入 Cubism 运行时。许可需按所选 SDK 与分发方式核对。

逻辑继续发出动作 ID、参数和桌面接触锚点；PNG 与 Live2D 只负责呈现。同一时刻只显示一个身体，切换需要完整的出入姿态与锚点匹配，不让两个渲染窗口叠出双影。缺少动作时回退 PNG，回退前取消 Live2D 持续动作权重、物理偏移和鼠标参数，恢复时同样清理 PNG 状态。

验收关注：正常速度与减速录屏下没有双头双手；身体比例与脚底高度一致；手动输入立即优先；休息与音乐动作能退出；窗口/图标接触点不漂移；切换模型失败后 PNG、拖拽和设置仍可使用。
