# 雪的行为逻辑总览

整理日期：2026-10-24。本文依据当前 `console-v2` 源码与动作配置重新核对，说明雪在正常启动后的实际行为，不包含未来设计。旧文档中与本文冲突的段落，以本文为准。

本文不把雪的动画解释成“AI 临时决定”。绝大多数动作由本地时间、用户设置、随机袋、桌面几何和声音特征触发，没有隐藏的饥饿、疲劳、亲密度或“自主打开文件”机制。动作名称也不代表一定检测到了对应现实事件，例如“打喷嚏”只是随机待机动作，不是检测到用户打喷嚏。

---

## 1. 运行结构与每帧顺序

### 1.1 模块分工

正常入口会创建并挂载下列模块：

| 模块 | 职责 |
|---|---|
| `DesktopPet` / `PetAnimator` | 窗口、渲染、主动画循环、鼠标与物理入口 |
| `IdleActions` + `IdleAnimation` | 清醒待机的姿态/动作抽取、间隔、呼吸与眨眼 |
| `DailyRoutine` | 按本地小时选择时段、动作偏好与节奏系数 |
| `SleepCycle` | 固定时段睡眠、入睡/唤醒过渡、清醒保护、图标旁休息点 |
| `Patrol` + `PlayPolicy` | 自主巡逻、图标小故事、侧边攀爬、出屏换层、三餐、零食、撒娇 |
| `IconSleep` | 桌面图标依靠、六种姿势、遮挡与停留 |
| `EdgeAttachment` | 手动拖放和飞行接触窗口/屏幕边缘、侧边爬行 |
| `MusicCompanion` | 系统播放声音监听与跳舞/好奇/轻晃 |
| `Speech` | 环境心声与聊天气泡 |
| `PetPresence` | 隐藏/显示时从屏幕边缘探头和退场 |
| `PatrolDepth` / `PatrolPassage` | 仅在完全出屏时切换窗口前后层级 |

`main.py` 正常启动时一定创建 `Patrol`。旧版 `pet.py` 中“没有巡逻模块时按概率左右走”的备用逻辑已删除，改用巡逻、图标依靠、贴近和指定目的地位移来驱动走动。

### 1.2 主动画帧中的更新顺序

`PetAnimator.tick` 每帧大致按以下顺序更新：

1. 清理已失效的巡逻任务。
2. 更新清醒待机调度（`idle.update`）。
3. 更新舞后恢复。
4. 推进当前动作帧。
5. 预加载睡眠素材（拖拽或物理中跳过）。
6. 更新睡眠、音乐、巡逻。
7. 更新环境心声调度。
8. 更新舞蹈舞台位移。
9. 更新人物位置。

位置更新有明确的先后优先级：

`睡眠过渡 > 显隐过渡 > 舞蹈舞台 > 抛掷物理 > 打滚位移 > 指定目的地位移 > 巡逻移动 > 停止`

这只说明同一帧里谁先写入位置，不等于所有行为共用一张简单的全局优先级表。动作播放、气泡和巡逻仍在各自阶段更新。

### 1.3 状态快照

对外状态通常分为：

- `sleep`：定时睡眠或入睡/唤醒过渡。
- `stand`、`sit`、`prone`：三种清醒待机姿态。
- `互动`：走路、拖拽、物理、图标依靠、边缘附着等。

动作存在素材库中，不等于会自动进入待机抽取。`blink`、`reading-pose-3`、`dance-rest` 等属于基础层或专用角色，不在普通自动动作名单里。

## 2. 三种清醒待机

三种清醒姿态是**站立、坐下、趴着**。睡眠是独立的第四种状态机，不参加普通待机抽取。

### 2.1 站立的基础层

站立是没有任何动作占用时的默认外观。

- 呼吸周期约 4.2 秒，用 64 个运动相位并在相邻相位之间插值，持续存在，不需要随机触发。
- 眨眼单独调度：一次结束后等 2.8～6.8 秒再启动下一次；约 20% 为连眨两次；闭眼通常保持 85～140 毫秒，连眨第二次约 75～120 毫秒。
- 呼吸和眨眼不会被“暂停”“安静”冻结；它们属于视觉基础层，不是普通待机动作。

### 2.2 三种姿态的自动动作池

配置来源：`assets/actions/idle-states.json`。

| 姿态 | 自动动作数 | 动作（配置键 / 中文名） |
|---|---:|---|
| 站立 | 18 | `comb` 梳头、`dress` 整理衣服、`read` 看书、`tea` 喝茶、`stretch` 伸懒腰、`wait` 等待、`yawn` 打哈欠、`screen` 口袋电子屏幕、`leap` 跳跃、`hum` 轻轻哼歌、`hair-tuck` 把发丝别到耳后、`sneeze` 打个喷嚏、`gaze-far` 眺望远方、`listen` 侧耳倾听、`warm-hands` 呵气暖手、`curtsy` 浅鞠行礼、`wave` 向你招手、`star-wish` 对星许愿 |
| 坐下 | 7 | `sit-neat` 端坐待机、`sit-relaxed` 抱膝待机、`sit-swing` 侧坐晃脚待机、`eat` 进食、`work` 工作、`reading-pose-1` 阅读姿势 1、`reading-pose-2` 阅读姿势 2 |
| 趴着 | 4 | `prone-chin` 托腮趴姿待机、`prone-rest` 枕臂趴姿待机、`lazy-roll-toward` 慵懒侧滚·朝向屏幕、`lazy-roll-away` 慵懒侧滚·背向屏幕 |

说明：

- 正常挂载巡逻后，`eat` 会从普通环境待机池中排除。吃饭改由三餐与零食任务负责，因此“坐着进食”不会随机出现，除非通过其他明确入口播放。
- `reading-pose-1/2` 是单帧静态动作。自动播放时会被保持 18～28 秒，期间继续获得呼吸微动，而不是只闪 0.45 秒。
- `sit-neat`、`sit-relaxed`、`sit-swing`、`prone-chin`、`prone-rest` 带有 `ground_idle` 标记，会延长中段休息帧。
- `sit-swing` 另带 `body_locked`：坐姿的水平位置已烘焙进像素，光流补间从固定后的图集重算，因此坐下与晃腿时身体不再横滑。
- `lazy-roll-toward/away` 不是原地换图，位移随动作姿势进度推进；自然结束后会衔接放松趴姿。

### 2.3 一次待机动作如何被选中

#### 候选范围

1. 取当前时段的 `only` 列表；没有 `only` 时取全部自动动作。
2. 并入该时段的 `preferred` 列表。
3. 与“自动动作名单”求交集，并检查素材是否可用。

因此时段既能整体收窄动作池，也能只给某些动作更高出现顺序，而不复制动作。

#### 姿态袋与动作袋

调度器使用两层“洗牌袋”：

- 动作袋：当前可用动作每轮各出现一次，取空后重建。
- 姿态袋：先抽站立/坐下/趴着，再从该姿态尚未使用的动作中取一个。

如果直接对全部动作等概率抽取，站立动作有 20 个，会长期挤掉坐姿和趴姿。姿态袋保证三种姿态轮流获得机会。

偏好动作的排序权重为 `random() ** (1/3)`，只把偏好动作排到本轮更靠前的位置，不会让它在袋子里出现三次。因此不能把它理解成精确的三倍概率。

同一轮中若还有别的动作可用，会尽量避免紧接着重复上一个动作。时段切换会清空动作袋和姿态袋，并按新时段重建。

#### 时间与打断

- 启动后第一次自动动作计划在 5～8 秒后。
- 每次动作开始后会重新安排下一次等待；等待时间见 2.4。
- 当前动作自然完成后，重新进入等待。
- 若动作被用户互动打断，解除阻塞后通常改为 3～6 秒再恢复，避免立刻抢回角色。

### 2.4 等待间隔与阻止条件

基础等待时间：

| 活跃度 | 基础间隔 |
|---|---:|
| 少动 | 22～34 秒 |
| 默认 | 12～22 秒 |
| 活跃 | 9～16 秒 |

实际间隔再乘以当前时段的 `pace`。这是“调度等待时间”，不保证到点一定出现新动作；已有动作、互动或阻塞都会让它继续等待。

以下情况会阻止新的普通待机动作；若已有自动动作正在播放，调度时会停止它：

- 窗口隐藏。
- 正在拖拽。
- 暂停或安静模式。
- 快速聊天请求处理中。
- 正在显示非环境气泡。
- 抛掷物理进行中。
- 显示/隐藏过渡中。
- 巡逻正在执行或处于巡逻模式。
- 音乐反应进行中。
- 正在走向指定目的地。
- 已依靠桌面图标。
- 已附着窗口或屏幕边缘。

没有动作、走路或上述阻塞且到达等待时间时，才会抽取下一个动作。

### 2.5 动作时长延长与收尾衔接

- `ground_idle` 动作：保留下坐/趴下、眨眼和起身段，只把中段中性休息帧延长，使总时长至少达到随机的 24～38 秒。原动作更长时不会缩短。
- 单帧动作：直接保持 18～28 秒，并继续应用呼吸形变。
- 自然完成且配置声明 `end_posture` 为 `sit` 或 `prone` 时，会衔接端坐或放松趴姿；衔接从已经坐下/趴下的位置开始，跳过再次下坐/趴下的开头，休息后再起身。
- 被用户打断时不会强行补播收尾。

### 2.6 每个动作的实际触发条件

绝大多数动作没有外部传感器触发，触发条件就是“当前姿态被抽中、时段允许、没有阻塞”。下表说明每个动作可能出现的入口，避免把动作名称误读成环境检测。

| 动作 | 普通待机 | 其他入口 | 实际条件 |
|---|---|---|---|
| 梳头、整理衣服 | 是 | 无 | 随机待机；晨起、傍晚偏好 |
| 看书 | 是 | 巡逻“读一会儿” | 随机待机；日间偏好；抬书后停留约 20～35 秒，期间持续呼吸、视线在书页与镜头间往复；巡逻链条先阅读姿势，再端坐 |
| 喝茶 | 是 | 巡逻“小茶歇” | 随机待机；午后偏好；巡逻链条为伸懒腰→喝茶→端坐 |
| 伸懒腰 | 是 | 巡逻茶歇 | 随机待机；晨起、午后偏好 |
| 等待 | 是 | 无 | 随机待机；上午偏好 |
| 打哈欠 | 是 | 无 | 随机待机；夜间、午间、睡前偏好 |
| 口袋电子屏幕 | 是 | 无 | 随机待机；不读取屏幕内容 |

| 轻轻哼歌 | 是 | 无 | 随机待机；不依赖音乐反应 |
| 整理鬓发、浅鞠行礼、向你招手、对星许愿 | 是 | 无 | 随机待机；不检测用户是否在看 |
| 打个喷嚏 | 是 | 无 | 随机待机；不检测喷嚏声或花粉 |
| 眺望远方、侧耳倾听、呵气暖手 | 是 | 无 | 随机待机；不读取窗外或环境温度 |

| 进食 | 配置中存在 | 三餐、零食 | 正常挂载巡逻时从普通待机池排除；只有吃饭任务播放 |
| 工作 | 是 | 无 | 随机待机；不检测前台应用 |
| 阅读姿势 1/2 | 是 | 巡逻“读一会儿” | 单帧动作自动保持 18～28 秒；巡逻保持 20～50 秒 |
| 托腮、放松趴着 | 是 | 巡逻打滚收尾 | 随机待机；夜间、午间、睡前偏好；打滚自然结束后接放松趴 |
| 朝内/朝外打滚 | 是 | 巡逻打滚 | 随机待机；需要下方或上方有足够空间，位移与动作同步 |
| 眨眼 | 基础层 | 无 | 独立计时，不经过动作袋 |
| 阅读姿势 3 | 素材存在 | 手动入口 | 不在自动名单 |
| 舞后休息 | 素材存在 | 音乐舞蹈自然结束 | 不在普通自动名单 |

## 3. 一天中的节奏

按电脑本地小时选择时段，不要求程序在整点启动。取“开始时间不晚于当前小时的最近一段”。

|---:|---|---:|---:|---:|---|---|
| 00:00 | 夜间休息 | 0 | 2.4 | 3 | 睡觉、放松趴、打哈欠 | 睡觉、放松趴、托腮、打哈欠、抱膝坐 |
| 07:00 | 晨起梳洗 | 0.8 | 1 | 1 | 伸懒腰、梳头、整理衣服、进食 | 无 |
| 09:00 | 日间阅读 | 1 | 1 | 1.3 | 看书、等待、喝茶 | 无 |
| 12:00 | 午餐与小憩 | 0.35 | 1.5 | 1.5 | 进食、抱膝坐、放松趴、打哈欠 | 无 |
| 13:00 | 午间熟睡 | 0 | 2.4 | 3 | 睡觉、放松趴、打哈欠 | 睡觉、放松趴、托腮、打哈欠、抱膝坐 |
| 14:00 | 午后茶与活动 | 1 | 1 | 1 | 喝茶、伸懒腰、看书、晃脚、两种打滚 | 无 |

注意：

- 夜间和午睡的 `only` 虽然包含 `sleep`，但 `sleep` 会被自动动作名单过滤，不会从普通随机池重新抽出睡眠。过滤后实际可抽到的是放松趴、托腮、打哈欠、抱膝坐。
- 23:00 进入夜间节奏，不等于定时熟睡从 23:00 开始；定时睡眠仍按第 4 节的固定窗口。
- 行走系数主要影响巡逻机会间隔；为 0 时普通巡逻不会发起。

## 4. 睡眠

### 4.1 固定时段

每天本地时间 **00:00～07:00** 与 **13:00～14:00** 为睡眠时段。判定条件等价于“小时小于 7”或“小时等于 13”。

状态顺序：

`awake（清醒） → settling（入睡过渡） → asleep（熟睡） → waking（唤醒过渡） → awake`

- 入睡过渡约 1.6 秒，按 60 帧/秒采样。
- 完整唤醒过渡约 1.0 秒。
- 熟睡呼吸为 96 帧、20 帧/秒，约 4.8 秒一轮。
- 入睡中被打断时，会按当前进度反向衔接，不会先闪成完全熟睡。
- 入睡过渡约 1.1 秒后 Z 字开始淡入；熟睡时保持 3 个 Z，按 4.8 秒循环。

### 4.2 入睡条件

同时满足以下条件才会进入睡眠：

- 当前处于睡眠时段。
- 不在巡逻探索模式。
- 已过清醒保护时间。
- 不忙碌：没有拖拽、物理、显隐过渡、图标/边缘附着、快速聊天请求、非环境气泡。
- 窗口可见。
- 没有未授权的普通动作占用。
- 未暂停。

安静模式本身不阻止入睡；暂停会阻止新进入睡眠。

### 4.3 清醒保护

- 点击、主动交流、拖拽等会唤醒，并设置约 120 秒清醒保护。
- 忙碌期间保护会继续向后延，每次延长 120 秒。
- 保护结束、仍在睡眠时段且空闲时，可以再次睡去。
- 睡眠时段结束会自动唤醒。
- 声音反应开启且监听有效时，较大的突发播放声音可以唤醒。
- 拖拽达到阈值后立即把姿态控制权交给拖拽，不等待唤醒动画播完。

### 4.4 图标旁的休息点

每次入睡尝试最多寻找一次图标旁休息点：

- 需要开启“自主图标互动”。
- 图标扫描结果不超过 3 秒。
- 附近存在可评分、路线露出的图标候选。
- 预计步行时间不超过 `min(6 秒, 当前剩余活动预算)`。

找到后先走过去，到达后设置休息点并正式入睡。最多等待约 10 秒；走不到、没有候选或等待超时，就原地入睡，不会为了图标耽误睡眠。

休息点建立后每秒复查：

- 图标移动、消失、扫描出错、屏幕/尺寸/位置变化或路线被挡时，只清除图标遮罩并继续原地睡，不会因此醒来。
- 手动图标依靠则是另一套模块，图标消失或姿势失效会直接醒来。

### 4.5 与其他“睡”的区别

- 定时熟睡：本节状态机，闭眼、呼吸、Z 字、睡眠时段。
- 巡逻“到图标旁小睡/依靠”：属于图标依附，模块里的 sleeping 只表示已靠住并停留，不一定进入定时睡眠的闭眼状态。
- 图标旁休息点：只是熟睡发生的位置，不改变睡眠状态机。

## 5. 自主巡逻

### 5.1 两种模式

- **日常巡逻**：默认开启。约每隔一段时间醒来一次，选择图标、散步、打滚、喝茶、休息等，完成后回到普通待机。
- **持续巡逻/探索**：通过“开始巡逻”命令进入，`start_once` 会先离开已有图标或边缘附着，然后持续选择目标，直到用户停止。持续巡逻中不会反复回到长时间普通待机。

正常启动默认是日常巡逻；持续巡逻需要明确指令。

### 5.2 什么时候尝试

- 初始计划在 45～80 秒后。
- 一次任务正常结束或被取消后，下一次等待 `60～120 秒 × 活跃度系数`，再除以 `max(0.3, 当前时段 walk)`。
  - 少动 1.6，默认 1.0，活跃 0.75。
- 探索模式没有目标时，间隔缩短为 3～8 秒；失败时 8～15 秒。
- 连续失败会额外退避，最长约 120 秒。
- 三餐和零食先于普通让路规则检查。

到期后仍可能延后：

- 用户最近 2 秒内有输入时，75% 概率延后 30～60 秒。
- 23:00～07:00 或当前时段 `walk <= 0` 时延后 30 秒。
- 仍在故事冷却中且活动预算不足 2 秒时延后，至少到冷却结束。

### 5.3 出发条件

需要：

- 窗口可见且处于期望的显示状态。
- 未暂停、未安静。
- 开启“自主走动”。
- 开启“自主玩耍”。
- 目标涉及图标时还需开启“自主图标互动”。
- 没有睡眠过渡、拖拽、物理、显隐过渡、音乐反应、指定目的地、快速聊天请求、非环境气泡、弹出菜单、已附着边缘或未被巡逻拥有的图标依靠。
- 当前时段允许行走。

普通日常巡逻要求路线包围矩形是露出的桌面；持续巡逻在后层模式下允许路线穿过普通窗口，但仍然必须满足支撑与遮挡规则。

### 5.4 图标候选如何评分

图标候选不是随机抓一个，而是先筛选再评分：

1. 计算图标下方、水平居中的休息位置，使头部落在图标下缘附近。
2. 距离上限为 `min(360, 宠物高度 × 2, max(65, 速度) × 7)`。
3. 避开鼠标：目标中心与鼠标距离至少 `max(120, 高度 × 0.65)`。
4. 评分：
   `0.30 × 距离得分 + 0.25 × 空间得分 + 0.20 × 新鲜度 + 0.15 × 休息倾向 + 0.10 × 熟悉度`
5. 新鲜度为 `1 / (1 + 访问次数)`，熟悉度为 `min(1, 访问次数 / 3)`；休息倾向为 `1 - 体力/100`，体力低时更偏向休息。
6. 对前 8 个候选做路线/遮挡探测，取最多 3 个安全候选，再按分数加权随机。

`PlayPolicy` 还会剔除：

- 仍在图标冷却中的图标。
- 最近失败且未过 120 秒的图标。
- 体力低于 30 时不做绕行；低于 15 时只允许休息类任务（活跃模式可不受此限制）。

### 5.5 一次日常任务的选择顺序

到期且通过检查后：

1. **持续巡逻专属**：满足时间条件时，25% 概率尝试出屏换层。
2. **持续巡逻专属**：28% 概率尝试窗口/屏幕侧边攀爬。
3. **图标故事**：有候选时，持续巡逻 85%、日常巡逻 65% 概率选择图标故事；故事种类从当前可用类型中随机。
4. **否则选择普通任务**：
   - 持续巡逻：打滚或散步。
   - 日常巡逻：打滚、散步、喝茶、休息。
5. 持续巡逻的第一次任务强制为散步，避免刚开始就原地坐下。

如果图标故事规划失败（例如图标文字旁没有安全空位、绕行空间不足、图标太高），会改为附近的安全散步，而不是把持续巡逻卡在空闲。

### 5.6 图标故事

| 类型 | 行为链 | 停留/条件 |
|---|---|---|
| `observe` 观察 | 好奇 → 抱膝坐 | 需要图标文字旁有安全位置 |
| `lean` 依靠 | 走近 → 接触后攀爬 → 六种姿势之一 | 停留 20～45 秒，再用同一支撑爬下 |
| `read` 阅读 | 阅读姿势 1/2 → 端坐 | 阅读保持 20～50 秒 |
| `orbit` 绕行 | 走到图标下方一侧 → 停 1～2 秒 → 走到另一侧 → 好奇 | 两侧都需露出，总时间不超过约 10 秒或剩余预算 |
| `peek` 窥看 | 播放 `play-peek` 并把图标图形从角色身上挖掉 → 抱膝坐 | 只在素材可用时进入 |
| `perch` 高台 | 爬上图标上沿 → 顶部休息 15～35 秒 → 爬下 | 需要图标图、宽度至少为角色宽度 15%、支撑点路线露出 |

共同规则：

- 依靠和高台都必须先在同高度接触支撑，再攀爬；不会空走向上。
- 图标在接近途中移动时，允许一次同屏重规划；消失、被遮挡或换屏则取消。
- 任务只播放自己拥有的动作；用户手动选择动作后，不覆盖用户选择。
- 完成后按类型记录冷却，并有 12% 概率说一句环境气泡（距离上次说话至少 180 秒）。

### 5.7 散步与打滚

**散步**

- 在附近随机采样目标，半径 `80～min(300, max(65, 速度) × 3)`。
- 目标与当前位置至少相距 60 像素。
- 路线必须露出，并避开鼠标 `max(120, 高度 × 0.65)`。
- 观察到出发前会有约 0.3 秒观察；行走中每 0.2 秒探测下一步是否被遮挡。
- 到达后播放“好奇”，不会在终点接坐下。
- 普通行走不会无支撑向上：若目的地在当前高度之上且没有已建立的攀爬，巡逻会取消这次移动。上升只能通过图标或边缘攀爬。
- 行走途中鼠标靠近角色中心 `max(100, 高度 × 0.5)` 内时会停下让出空间；接近图标时使用更大的 `max(120, 高度 × 0.65)`。
- 接近目标时自动减速，速度最低可降到约 10 像素/秒。
- 日常巡逻单次移动累计超过 12 秒会停下；持续巡逻受活动预算约束。

**步态呈现**

- 行走由 `walk_rig.py` 实时合成：身体图加两条刚性小腿图，支撑腿只做平移，摆动腿绕裙下髋点做约 3° 的轻微俯仰，运行时不逐帧解码图片。
- 步态由实际位移推进：一个完整周期 40 显示像素（源图 64 像素，默认步速下约 1.28 秒），支撑相固定占 50%，两只脚在同一帧交接支撑，没有双脚同时平放的停顿。
- 双脚的脚底接触点固定在源图横坐标 107.25/156.75，摆动则围绕身体中线附近的 home 点 124/132（以身体中心 x=128 为中点、相距 8 源像素；待机原画为 116.6/136.8）。近脚鞋底落在 y=249 的地面线；远脚是侧视平底鞋，鞋底约在 y=241，比近脚高一层景深，落地时整条鞋底先着地，不再出现脚尖先触地的角度。行走时裙摆和身体整体下沉 4 源像素，让露出的袜长更短。
- 每步支撑脚相对身体后移 32 源像素，鞋底始终钉在同一世界坐标；摆动脚抬升 10 源像素，并按旋转后的最低鞋底点保持在地面之上。
- 抬脚使用 `1 - cos⁶(πu)` 曲线：接触瞬间位置和速度都连续，但离地明显更快，因此每一步落地后不会再有“站稳一下”的滞留。
- 摆动腿在离地后脚尖略向下、落地前脚尖略抬起，到接触帧俯仰回 0°，所以仍由整条鞋底平放着地；支撑相全程不旋转。
- 两只鞋的远近层级固定为远腿在下、近腿在上，不随相位交换；两只鞋围绕以身体中心 128 为中点、相距 8 源像素的落脚点前后交替，行走时轮廓会重叠、交叉，近腿始终压住远腿。
- 头部和裙装不拉伸，身体做约 1.1° 的反向轻摆，并叠加约 1.2 源像素的上下起伏（接触时最低、支撑中期最高）。
- 停下时步态能量在 0.18 秒内衰减（另有 0.02 秒宽限），双脚在 0.32 秒内回到与待机原画一致的站位；之后用最多 0.18 秒的短交叉淡入待机，轮廓接近时缩短为 0.055 秒，避免出现“四只鞋”的重影。
- 正面 / 背面走路由 `vertical_walk_rig.py` 实时合成：窗口位移跟随两步节奏，落脚时减速、抬腿时前进，不再匀速平移；支撑脚在画布内小幅后移（4 源像素）配合裙下髋点交替换步，抬脚 16 源像素。身体摇摆与滚转较旧版收敛（sway 3.4、roll 1.4 源像素），整体保持稳定。

**打滚**

- 日常巡逻随机朝内或朝外；持续巡逻固定朝外（远离屏幕中心方向）。
- 巡逻打滚位移上限为 `min(70 × 高度 / 180, 可用空间)`；普通待机/手动打滚为 `150 × 高度 / 180`。
- 所需空间至少为 `min(35, 高度 × 0.3)`，不足则换任务。
- 自然结束后衔接放松趴姿；用户打断则不补播。

### 5.8 侧边与出屏

**侧边攀爬（持续巡逻）**

- 从缓存的窗口/屏幕表面中选择左/右边。
- 抓握高度必须等于当前行走高度，不允许通过空走向上获得高度。
- 横向距离不超过 `max(360, 宽度 × 3)`。
- 靠近后调用边缘附着进入攀爬，停留 18～35 秒，随机向上或向下爬 30～90 像素，再放开。

**出屏换层（持续巡逻）**

- 每 60～120 秒考虑一次，首次计划在 45～90 秒；概率 25%。
- 横向走到屏幕外，确认整个宠物窗口完全不可见后才切换自身窗口层级。
- 单屏可以从屏幕外改变返回高度；多屏只选择不会在相邻屏幕暴露隐藏过程的侧边，并保持同一高度。
- 没有合适侧边时放弃本次出屏。
- 处于后层时允许被应用窗口完全挡住，不强制定时回到前方；下一次出屏才切回。
- 程序只改变自己的窗口层级和遮罩，不移动、激活或修改第三方窗口。
- 巡逻结束会恢复用户原本的置顶偏好。
- 出屏途中被打断，会先把角色安全放回屏幕内。

### 5.9 三餐、零食与撒娇

| 行为 | 时间窗口 | 规则 |
|---|---|---|
| 早餐 | 07:00～09:00 | 每天一次；播放进食并显示对应气泡 |
| 午餐 | 12:00～14:00 | 每天一次；13 点后可能受熟睡阻止 |
| 晚餐 | 18:00～20:00 | 每天一次 |
| 零食 | 09:00～21:00 | 随机等待 20～40 分钟；仍需通过巡逻阻塞检查 |
| 撒娇 | 07:00～23:00 | 至少 5 分钟没有被点击，每 300 秒最多一次，当前时段允许行走 |

- 三餐只有动作自然完成才写入当天完成标记并保存；被打断不算吃完。
- 失败重试至少相隔约 90 秒。
- 用餐开始会把下一次零食推迟到至少 15 分钟后。
- 因为三餐和零食归巡逻模块管理，关闭“自主走动”会一起关闭自动吃饭和零食，不只是停止走路。
- 撒娇只在点击冷却满足时出现，不与图标故事共用冷却表。

### 5.10 失败、冷却与预算

- 故事冷却：日常 480 秒，持续巡逻 45 秒。
- 同一图标冷却：日常 300 秒，持续巡逻 60 秒。
- 最近两个故事类型不会连续重复。
- 连续完成 2 个故事后进入 180～360 秒安静期。
- 图标失败后 120 秒内不再选该图标。
- 活动预算：少动每 10 分钟 30 秒移动，默认 60 秒，活跃不限。
- 体力：移动时每秒约 -0.35，静止每秒 +0.025，熟睡每秒 +0.12。
- 好奇度随时间上升，完成故事下降 20；它目前只作为内部状态展示，不直接参与候选评分或冷却计算。

## 6. 桌面图标互动

### 6.1 只读发现

程序通过 Windows Shell 的只读接口读取桌面图标：

- 查找桌面的 `SHELLDLL_DefView` 与 `SysListView32`，读取图标名称、位置、图形和文字边界。
- 图标大小限制在 16～256 像素，数量上限 2000。
- 图标身份使用解析路径的 SHA-256 前 24 位，图标移动后仍能识别同一对象。
- 读取的是物理像素坐标，再按所在显示器转换到 Qt 逻辑坐标。
- 只读取图标位置与轮廓，不打开文件、不移动图标、不修改桌面。
- 图标被任何可见窗口遮挡时，不参与拖放停靠；持续巡逻在后层模式可以接近被窗口挡住的图标，因为角色本身也允许被挡。

### 6.2 三条进入路径

**路径 A：巡逻自行接近**

- 需要“自主图标互动”开启。
- 不要求“拖放即时吸附”。
- 走图标故事流程，可依靠、阅读、绕行、窥看、上高台。
- 由巡逻自己的任务身份管理，取消时只清理自己拥有的动作和依靠。

**路径 B：手动图标依靠/小睡**

- 通过 IPC `start_icon_sleep`，或工作台选择图标后启动。
- 会先取消音乐和巡逻，再让角色走向目标。
- 使用设置中的方向、偏移、呼吸幅度和停留分钟数。
- 这是“依靠/停留”，不是定时睡眠状态机。

**路径 C：拖放停靠**

- 松手时先尝试图标，再尝试窗口/屏幕边缘，最后才进入抛掷。
- 需要“拖放即时吸附”开启。
- 图标扫描结果不超过 3 秒。
- 图标不能被窗口遮挡。
- 判定使用图标图形区域：指针在图标框外不超过 `min(30, 半径)`，或角色脚部中心落在半径 `min(snap_distance, max(36, 宽度 × 0.45))` 内；取距离最小者。
- 命中后立即对齐并采用自动姿势，不继续抛掷。

### 6.3 姿势与几何

六种姿势：

| 姿势 | 支撑方式 | 目标接触点 |
|---|---|---|
| `sit-front` | 图标上沿，正面坐 | 顶部中点 |
| `sit-back` | 图标上沿，背面坐 | 顶部中点 |
| `prone-front` | 图标上沿，正面趴 | 顶部中点 |
| `prone-back` | 图标上沿，背面趴 | 顶部中点 |
| `perch-front` | 图标右侧，正面倚靠 | 右侧约 0.9 |
| `perch-back` | 图标左侧，背面倚靠 | 左侧约 0.1 |

- 自动放置按优先级 `sit-front → sit-back → prone-front → prone-back → perch-front → perch-back → left → right → back` 生成候选，再选择位移最小且能完整留在屏幕内的一种。透明边距和相邻图标文字不视为障碍。
- 手动拖放或巡逻依靠使用 `auto_pose` 时，会从六种新姿势中随机选一种；若几何不适配则继续寻找。
- 手动 IPC 启动且方向为 `auto` 时，会按几何选择合适姿势，而不是每次随机。
- `left/right/back` 是兼容旧姿势，仍可用于手动方向设置。
- 新姿势为 16 帧、6.4 秒循环，并带呼吸；眨眼安排在约 3.2 秒和 8.05 秒附近。
- 呼吸时保持接触点不动，只做轮廓缩放，避免角色在图标上“漂移”。

### 6.4 遮挡与失效

- 图标依靠只把“图标图形与裙装区域的交集”从角色遮罩中挖掉，头发保持在前景。
- 不会为图标文字或其他图标挖洞。
- 图标移动、删除、图形缺失、对齐失败时：
  - 手动依靠会醒来并解除。
  - 巡逻依靠由巡逻任务取消并清理。
  - 睡眠休息点只清除遮罩，继续原地睡。
- 巡逻接近途中若目标移动、消失或路径被挡，会取消本次任务，不会继续吸附旧位置；如果距上次环境反应已超过 35～60 秒，会先播放一次“好奇”或“倾听”再停下。
- 停留时间设置为 0 表示不因计时自动结束；否则按分钟计时，到点醒来。
- 图标扫描后台进行，扫描本身不会让角色自动靠近图标。

### 6.5 图标依靠设置

| 设置 | 默认 | 范围/说明 |
|---|---:|---|
| 方向 `direction` | `auto` | 自动、六种新姿势或旧左右/背面 |
| 水平偏移 `offset_x` | 0 | -100～100 |
| 垂直偏移 `offset_y` | 0 | -100～100 |
| 呼吸幅度 `breath` | 55 | 0～100 |
| 停留分钟 `duration` | 0 | 0～120；0 为不限时 |
| 吸附距离 `snap_distance` | 100 | 30～240 |

图标依靠模块本身不再保存吸附开关；观察与失效重扫统一读取全局“拖放即时吸附”。

## 7. 窗口与屏幕边缘

### 7.1 入口

1. **手动拖放**：松手时图标优先；没有图标命中才尝试边缘。需要全局“拖放即时吸附”开启。
2. **飞行接触**：抛掷过程中，若角色真实轨迹穿过窗口边缘支撑，由边缘附着接管。需要吸附开启且窗口候选开启；只抓窗口，不抓屏幕边缘。
3. **持续巡逻自主攀爬**：仅在探索模式，且通过活动策略与缓存表面检查；先同高度走近，再抓住侧边。
4. **自主窗口上沿停靠**：开启“自主窗口互动”时，偶尔跳上前台窗口上沿；专注、睡眠、拖动时让路。
5. **日常陪伴被动侧边互动**（2026-10-27）：不启动巡逻时，低频扫描当前屏幕真实可见窗口；偶尔选择左右侧边，同高度走近后抓框上下爬 15～28 秒再松开。只使用非全屏、非最大化窗口的真实侧边；屏幕边、任务栏与应用正文不进入候选。

`enabled` 与 `delay` 是历史设置：定时器只跟随已经建立的支撑，不会按这两个值主动寻找窗口。被动窗口侧边、自主上沿停靠以及主动巡逻中的窗口侧边由“自主窗口互动”开关控制，不读 `enabled/delay`；主动巡逻原有的屏幕边缘攀爬不受该开关影响。实际手动/飞行入口首先检查全局 `auto_snap`。

### 7.2 支撑位置与表现

| 位置 | 表现 |
|---|---|
| 窗口上沿 | 轻松休息 |
| 窗口下沿 | 抓住、悬挂 |
| 左右侧边 | 抓框；建立后可上下爬行 |
| 最大化/全屏窗口附近 | 按几何规则停在角落 |
| 可用屏幕边缘 | 在允许且无遮挡的位置停靠 |

- 全屏/最大化前台窗口的角落优先只用于非自主入口。
- 手动放置时，落点距离锚点不超过 `max(48, 宽度 × 0.6)`；或非角落情况下指针距锚点不超过 28 像素且不超过上限的 1.6 倍。
- 命中后立即对齐，不受停留计时、走路或暂停影响。
- 侧边爬行：每次休息 2～5 秒，再选择上/下 25～100 像素目标，以约 25 像素/秒移动，并限制在可支撑区间。
- 侧爬的手臂形变由 `climb_rig` 完成，脸部椭圆区域（眼睛、鼻子、嘴与额头前发）保持刚性；爬行过程中整张脸不参与位移，手臂和外侧头发仍然活动。
- 被动侧边互动的窗口列表由闲置时低频扫描预热；走近阶段约每秒复核，窗口移动、消失或最小化则取消；抓住后跟随窗口，窗口消失即从当前位置物理下落。上沿停靠继续只选前台窗口。
- 安静或暂停时停止自主爬行；跟随支撑窗口的被动位移仍会继续。
- 窗口移动或缩放时保持相对支撑；窗口关闭、最小化、隐藏或切到其他虚拟桌面时立即解除附着，并按拖动松手后的同一套物理下落（零初速度、重力、落地回弹与恢复）从当前位置掉下来。其余支撑失效或空间被遮挡到无法维持时仅解除，不触发下落。
- 跳跃靠近窗口的途中若目标窗口消失，也从空中当前位置直接下落，不补完到已不存在的窗口上沿。
- 模块不会激活或移动其他应用窗口。

## 8. 点击、拖拽、抛掷与菜单

### 8.1 单击

- 左键按下会立即唤醒睡眠、取消物理、停止当前动作、取消音乐、打断巡逻、隐藏环境气泡。
- 按下时先不显示反馈，因为这次按下可能变成拖拽；避免在拖动阈值处闪一帧。
- 松开且没有拖动时，立即播放“害羞”表情：单帧表情保持约 1.1 秒，并叠加弹簧/挤压变形。
- 不存在单击等待计时器：松手即判断可见性，可见就直接播放害羞。
- 睡眠中被点击时，优先完成唤醒动画，不叠加站立害羞。

### 8.2 双击

- 双击与单击使用同一个害羞表情反馈。
- 第二次按下会抑制随后松开的尾随单击，避免播放两遍。
- 当前没有单独的“摸头”动作分支。

### 8.3 拖拽

- 超过系统拖动阈值后进入拖拽反馈，角色跟随鼠标。
- 拖拽会中断巡逻、音乐、图标依靠和边缘附着。
- 拖拽期间不播放普通待机，也不进入睡眠。
- 松手顺序：图标停靠 → 边缘停靠 → 抛掷物理。
- 抛掷初速度用最近约 120 毫秒的鼠标轨迹拟合，上限 1600 像素/秒。
- 重力约 `1500 × 尺寸比例`。
- 碰侧边水平速度反向乘 0.58，碰顶部竖直速度反向乘 0.35，落地反弹竖直速度乘 0.60、水平速度乘 0.72。
- 落地速度低于阈值后停止反弹，播放约 0.96 秒恢复动作。
- 空中按住会停止飞行；未拖动就松开，会以零初速度重新下落，避免悬空。
- 飞行中真实接触窗口边缘会转入附着。

### 8.4 菜单与聊天

- 右键菜单打开前会取消音乐并打断巡逻；关闭后巡逻进入 10～20 秒的安静间隔。
- 菜单包含快速聊天、划词翻译、打开工作台和退出等入口。
- 用户聊天气泡优先于自主行为；聊天结束后的巡逻间隔为 30～60 秒。
- 快速聊天请求处理中会阻止普通待机、巡逻和入睡。
- `greeting` 设置只影响 IPC `jump` 时的问候气泡（“喵～你好呀”），不影响点击；点击不会因为该设置额外说话。

## 9. 音乐、气泡与显隐

### 9.1 音乐反应

- 监听的是系统播放回环，不是麦克风。
- 稳定节奏持续至少 4 秒并遇到节拍起点时尝试跳舞；舞蹈持续 30～50 秒，并在乐句边界收尾。
- 突然声音可触发约 4 秒好奇。
- 柔和/活跃声音持续至少 8 秒可触发约 5～9 秒轻晃。
- 跳舞速度随节拍调整。
- 舞蹈不是原地播放：窗口位置会按编排步法随支撑脚移动。步法路线放不进当前屏幕时，舞蹈会停止，而不是把脚位强行夹回屏幕内。
- 夜间时段不启动普通音乐反应，并延后约 40 秒。
- 声音停止、特征超时、动作所有权被接管或进入阻塞状态会取消。
- 舞蹈自然结束后有 12～20 秒恢复间隔，并可能衔接舞后休息；用户打断则不补播。

### 9.2 环境心声

- 启动后首次约 25～45 秒。
- 之后每次间隔 `90～180 秒 × 当前时段 speech`。
- 必须没有气泡、未安静/暂停、开启“自主短句”、没有走路/动作/快速聊天请求。
- 睡眠时不说环境心声。
- 台词来自当前时段预设文本，避免紧接着重复上一句；不是每次请求模型。
- 用户聊天气泡会让巡逻和音乐让路；超过 120 字时按标点分页，以约 36 字/秒显示。

### 9.3 显示与隐藏

- 隐藏/显示不是瞬间消失，而是从最近的屏幕侧边探头或退场。
- 过渡期间会阻止普通待机、巡逻、睡眠进入和音乐反应。
- 过渡结束恢复原调度。

## 10. 交互优先级与打断结果

| 事件 | 立即效果 | 后续 |
|---|---|---|
| 左键按下 | 唤醒睡眠；取消物理；停止动作/音乐；打断巡逻；清环境气泡；可能开始拖拽 | 单击松开播放害羞；拖拽则跟随鼠标 |
| 双击 | 与单击相同反馈；抑制尾随单击 | 不播放额外动作 |
| 拖动超过阈值 | 进入拖拽反馈；停止自动行为 | 松手后尝试图标/边缘，否则抛掷 |
| 右键菜单 | 取消音乐；打断巡逻 | 关闭后巡逻等待 10～20 秒 |
| 用户聊天 | 唤醒睡眠；取消音乐；打断巡逻 | 对话结束后巡逻等待 30～60 秒 |
| 暂停 | 阻止普通待机、巡逻、音乐、入睡 | 不冻结呼吸/眨眼基础层 |
| 安静 | 阻止普通待机、巡逻、音乐、环境心声；停止自主爬行 | 不阻止已有睡眠继续，也不阻止手动动作 |
| 隐藏 | 阻止自主行为；开始退场过渡 | 显示后恢复调度 |
| 拖动尺寸/置顶变化 | 释放边缘和图标依靠；取消巡逻 | 按新几何重新计算 |
| 睡眠时段开始 | 取消巡逻/音乐/移动/动作/气泡 | 尝试图标旁休息点，否则原地入睡 |
| 睡眠时段结束 | 自动唤醒 | 设置环境心声至少延后 5 秒 |

## 11. 设置对行为的实际影响

| 设置 | 代码键 | 默认 | 实际影响 |
|---|---|---:|---|
| 尺寸 | `size` | 100 | 50～200；影响窗口、图标姿势、物理尺度和部分距离 |
| 不透明度 | `opacity` | 100 | 30～100 |
| 始终置顶 | `always_on_top` | 开 | 出屏换层时临时改变，结束后恢复 |
| 速度 | `speed` | 48 | 10～150；移动实际使用 `max(65, speed)`，因此低于 65 的差别主要影响少量距离计算 |
| 活跃度 | `activity` | 默认 | 待机间隔、巡逻间隔、活动预算、体力限制 |
| 自主走动 | `random_movement` | 开 | 控制巡逻；同时影响三餐、零食、撒娇，因为它们在巡逻模块内 |
| 自主玩耍 | `autonomous_play` | 开 | 关闭时巡逻整体阻塞，包含图标故事、打滚、三餐和零食 |
| 自主图标互动 | `autonomous_icons` | 开 | 控制图标候选、图标故事、睡眠休息点；不控制手动拖放 |
| 自主窗口互动 | `autonomous_windows` | 开 | 控制日常被动窗口侧边、自主上沿停靠，以及主动巡逻中的窗口侧边攀爬；关闭时结束未转手动的自主窗口任务；不控制屏幕边缘攀爬与手动拖放 |
| 自主短句 | `autonomous_speech` | 开 | 控制环境心声；不控制用户聊天 |
| 问候气泡 | `greeting` | 开 | 仅影响 IPC `jump` 的问候文本 |
| 安静 | `quiet` | 关 | 阻止多数自主行为；不冻结呼吸/眨眼；不阻止手动动作 |
| 暂停 | `paused` | 关 | 阻止自主行为和新入睡；不等于所有动画冻结 |
| 拖放即时吸附 | `auto_snap` | 开 | 控制拖放图标/边缘停靠与飞行抓边；不控制巡逻自行找图标 |
| 音乐反应 | `music_reactions` | 开 | 控制系统播放监听与舞蹈/好奇/轻晃 |

实际效果还会受已保存设置、桌面图标扫描、窗口遮挡、显示器布局、音频设备和素材可用性影响。

## 13. 与旧文档的差异和验证边界

本文修正了旧版《Yuki 当前行为逻辑说明》中已被当前代码取代的内容：

1. 单击不再等待双击判定，松手即播放害羞；双击使用同一反馈，而不是摸头。
2. 问候气泡只由 IPC `jump` 触发，点击不会额外问候。
3. 正常启动始终有巡逻模块；旧版“无巡逻时按概率走路”的分支已从代码中删除。
4. 巡逻已支持图标六种姿势、阅读/绕行/窥看/高台故事、持续巡逻侧边攀爬、完全出屏换层和体力/预算限制。
5. 普通巡逻不再要求整条路线矩形完全露出；持续巡逻在后层模式允许接近被窗口挡住的图标。
6. 图标旁睡眠休息点是可选位置，不是独立睡眠机制；休息点失效只清遮罩，不强制醒来。
7. 边缘附着仍以拖放和真实飞行接触为主入口；历史 `enabled/delay` 不是自主寻找窗口的定时器。

本文依据源码与配置交叉核对，未启动应用做桌面目视验收，也未把历史截图当作本次运行证据。具体概率与时序是当前调度参数，不保证用户在指定秒数一定看到某个动作。实际 Windows 桌面上的多显示器、窗口遮挡、图标扫描和音频设备差异，仍可能改变最终表现。
