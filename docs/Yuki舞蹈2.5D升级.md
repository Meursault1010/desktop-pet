# Yuki 舞蹈：关闭光流后的修复版

本版替代之前的光流补间舞蹈。桌宠及工作台素材已更新；正在运行的 Yuki 需要重启加载新版代码与缓存。

## 本次修复

旧版离线构建使用双向 DIS 光流、图像重映射及轮廓变形，在较大转身、抬腿、手臂换位时会产生五官拉扯和轮廓变形。仅关闭实时运算无法消除已经烘焙进图集的变形帧，因此本次重新生成了全部运行图集。

- 从舞蹈构建入口删除光流计算、图像重映射与轮廓变形。
- 逐帧直接使用已有原画，保留 52 张原有姿势与 2 张已生成的转身姿势。仅执行统一留白和等比缩放，不混合两张图、不拉伸四肢。
- 逐帧停留约 100–170 毫秒，按姿势差异调整。往返循环共 106 个图集单元、14.058 秒。它是原画逐帧播放，不能等同于此前的 60 FPS 连续补间。
- 保留脚步驱动的窗口位移；去掉光流后重新从原画测量支撑点，没有沿用旧变形图的接地轨迹。
- 脚步回程同时反转画面与位移，保持循环接回；不使用椭圆路线或角色缩放。标准尺寸横向范围约 21 像素。
- 重新导出运行分页、完整图集和工作台无损 WebP 镜像，清除多余旧分页。
- 修复预览脚本隔帧取样的问题，新预览包含全部 106 帧及各帧真实时长。
- 独立脚步重建入口拒绝光流素材，防止重新启用旧变形帧。

移动仍根据二维原画估计选定支撑点，并非三维骨骼约束。屏幕空间不足时取消本次舞蹈，不强制夹住窗口继续滑脚；交互中断后留在当前位置。

## 2026-10-30 循环接缝与窗口起伏

原片是像素回文（f(k) 与 f(106-k) 完全同图），循环点上依次是 f1(124ms)、f0(279ms 定格)、f1(124ms)，同一个姿势被拖成约半秒静止。本轮只删两帧：定格帧 f0，以及头部那份重复的 f1（尾部的 f105 就是同一姿势，保留它，dance-rest/01 靠它对齐）。结果 104 帧、13.655 秒，接缝变成 f105(1)→f2 的普通一步。

没有照原话删尾部 f103–f105：那三张是回程最后三步，删掉后接缝跳到 f4→f1，差值 82.6，是全片最猛的一次跳变（常规相邻步中位 56.3、p90 69.9），并且会让舞蹈末帧不再是 dance-rest 的入场姿势。

起伏写在 `footwork.json` 的 `root[1]`：以每次 `support` 换脚为一步，抬升放在步中、落地放在换脚处，短促的单帧步按 300ms 归一自动减半，再做三帧平滑。总行程 4.50 px（-3.33…+1.17），最大 2.29 px/帧、平均 0.76；同支撑脚横向落脚位移仍为 0.00 px；`bounds` 同步扩到 `[-18.125,-3.33]…[3.125,1.17]`，贴边判定不变。第一帧 root 归零，起跳不位移。

重建与验收脚本在 `console-v2/action-work/dance-fix/`（`rebuild.py` 读 `backup-20261030-111202` 的原片，`verify.py` 逐项比对，`apply.py` 备份后落地）。工作台镜像 `frontend/dist` 需要重新 `npm run build` 才会更新。

## 2026-10-30 中间画画风统一

104 帧里有 39 帧（对应 20 张 `inbetween-*` 画稿）明显比关键帧糊：256px 图集上边缘斜率只有 30–40，关键帧是 118；抗锯齿过渡带宽度是 2.5 倍；在 160px 实际显示尺寸下锐度低 30%。原始生成图本身就只有约 200×230、斜率 24，不是缩放造成的。它们成段夹在清晰帧之间，播放时像反复失焦。

后处理救不回来：普通 USM、双边引导锐化、DoG、局部对比度在 160px 下几乎无变化（80.5 → 80.0）；在原始分辨率做 Richardson–Lucy 反卷积能到 62–76，但眼睛出现空心、发丝出现白点。

最终用约束式改图重画这 20 张：每张以原稿为姿态参考、两张清晰关键帧（或脸部/裙摆细节裁切）为画风参考，并在提示里**逐帧写明姿势**（哪只手举到哪、哪只脚在前、身体转向哪边）——不写姿势描述时，模型会把交叠的手画成张开。重画结果按脚底与高度配准回原稿坐标后再入图集。

验收：整体轮廓 IoU 中位数 0.958（17/20 ≥ 0.94，最低 0.883），手臂段 IoU ≥ 0.93；重画后中间画斜率 110、关键帧 119，160px 下差距从 −30% 收到 +1%。逐帧脚底基线仍是 20/233。

流程脚本在 `console-v2/action-work/dance-fix/style/`（`register_all.py` 配准打分、`install_redraw.py` 备份后替换源图并重建图集/分页/webp）。

## 2026-10-30 中间画裙子配色偏冷

重画解决了锐度，却带进了配色偏差：20 张 `inbetween-*` 的裙子整体比关键帧**更冷、更深**。用饱和度分离掩膜（裙子 S 中位数 0.39、p5 0.20；头发含淡紫阴影在内 p95 只有 0.14，阈值取 S>0.16 即可完全分开）逐张量：

| 组 | 裙子 L\*/a\*/b\* | 相邻帧裙子色差（\|ΔL\|+\|Δa\|+\|Δb\|） |
| --- | --- | --- |
| 关键帧 61 帧 | 82.7 / −1.3 / −20.5 | 全片中位 3.72、p90 8.70、峰值 11.51 |
| 中间画 39 帧（改前） | 80.8 / −3.5 / −21.6 | 与中间画相邻的跳变平均 6.37 |
| 中间画 39 帧（改后） | 82.4 / −2.0 / −21.4 | 与中间画相邻的跳变平均 2.65 |

原因是生成源图本身就偏：原始出图裙子 a\*≈−4.5、b\*≈−24，抠绿幕与配准只是让它更冷一点，不是流水线引入的（`repair_cell` 对颜色零改动，实测源图与图集格子 Δ=0）。

修法是逐张把裙子拉到关键帧中位（偏移量，不是混合），只动裙子区域：掩膜取饱和蓝主体 + 闭运算 + 最大连通域 + 补洞（补进裙摆蕾丝），再扣掉发丝样和皮肤样像素、向内腐蚀 1px、1.1σ 羽化。偏移上限 L±4、a±5、b±4，按渲染后的 256px 格子闭环迭代 3 次收敛，残差中位 0.03/0.05/0.13。头发、皮肤、眼睛的位移都 ≤0.15，未受影响。

全片 104 帧逐帧量的结果：相邻帧裙子色差中位 3.72→2.13、p90 8.70→4.64、峰值 11.51→7.46，循环接缝 5.12→3.09；关键帧↔关键帧的跳变保持 2.21 不变，说明只有中间画被改动。把舞裙与待机对照过：`blink` 84.5/+0.6/−16.0、`hum` 81.9/+0.7/−20.8、`sad` 83.7/−0.7/−17.6，待机自身就有约 5 个 b\* 的区间，舞蹈关键帧（−20.5）落在区间内，所以没有继续往某一张待机帧上对齐。

脚本：`action-work/dance-fix/style/color_lib.py`（掩膜与 Lab 换算）、`color_fix.py`（逐张校准，输出 `color-fixed/`）、`color_verify.py`（改前后的分组中位与逐帧跳变）、`color_rank.py`（53 张原画按色偏排序）。落地仍走 `install_redraw.py <dir>`，会重建图集、分页、poster 与 webp 并更新 `choreography.json` 的 `cell_sha256`。
