# 云端模型配置体验升级方案

> 范围：连接测试反馈、API 密钥管理、云端附件发送确认、模型配置档案管理。本文是后续实施与验收依据，不代表文中“待升级”能力已经实现。
>
> 依据：当前 `ModelSettings.tsx`、`model-config.cjs`、`PRODUCT.md` 与《云端模型使用说明》。本方案沿用工作台现有 Quiet Orbit 风格，不另起视觉体系。

## 1. 当前基线

已具备的能力：

- “测试连接并读取模型”可临时使用输入的密钥；测试本身不保存配置。
- 连接测试区分认证拒绝与模型列表不可用等部分结果；无模型列表时允许用户手动填写模型。
- 主连接密钥可加密保存、保留现有密钥或随配置保存操作删除。
- 配置档案默认不保存密钥；用户可以显式选择加密保存。档案列表目前显示“已配置密钥/无密钥”。
- 云端附件授权默认关闭，绑定当前端点；切换到另一个端点时授权会关闭。附件 UI 已说明图片会附带本机 OCR 文字。

本次要完成的体验缺口：测试反馈还不够结构化；密钥清除动作不够醒目且与普通保存耦合；附件目前通过设置中的常驻开关授权，发送前缺少逐次确认；档案删除没有确认，覆盖保存与密钥影响提示不足。

## 2. 目标与边界

让用户在执行会影响凭据、隐私或已保存档案的动作前，明确知道结果和数据去向；让连接问题能被用户定位；减少误删、误覆盖和误发。

本次限定在既有 OpenAI Chat Completions 兼容接口及当前模型配置页内，不扩展新的模型协议、不上传附件到 Yuki 自有服务、不建立云端账号或密钥代理。所有提示必须对应实际请求行为，不能仅靠文案替代后端授权检查。

## 3. 连接测试反馈升级

### 3.1 交互

保留“测试连接并读取模型”按钮，将测试结果显示在按钮附近的结果面板中。结果使用清晰状态标题、简短原因和下一步建议，不只显示原始错误文本。

| 状态 | 判断依据 | 建议反馈 |
|---|---|---|
| 可用 | HTTPS/API 地址有效，模型列表读取成功；输入模型存在时可确认匹配 | “连接成功，读取到 N 个模型”；列出模型并允许选择 |
| 需手动填写模型 | 服务返回 404/405 或明确不支持模型列表 | “服务未提供模型列表。密钥未验证；请按服务商文档填写模型 ID。”提供手动输入说明 |
| 认证失败 | 401/403 | “服务拒绝访问。检查密钥、账号权限和模型访问权限。” |
| 地址或协议错误 | URL 校验失败、远程 HTTP、URL 含凭据等 | 指出 HTTPS 要求或需填写 API 根地址；不展示敏感 URL 参数 |
| 超时/网络失败 | 超时、DNS、TLS 或连接错误 | “无法连接服务。检查网络、地址和服务状态后重试。”保留可展开的脱敏技术细节 |
| 服务响应异常 | 非预期状态码、响应结构错误或模型列表格式不兼容 | 显示状态码与通用恢复建议；不得回显响应中的密钥或完整请求头 |

### 3.2 测试语义

- 明确区分“连通性”和“密钥已验证”：服务不支持模型列表时，不得显示连接/密钥验证成功。
- 对于列表端点成功但空列表的情况，说明服务可响应但未返回模型，并允许手动填写。
- 若用户填写了模型 ID，结果应显示该 ID 是否出现在返回列表中；不在列表中时提示可能是权限或 ID 不匹配，仍允许保存以兼容服务端别名。
- 测试结果仅对当前端点、模型和本次密钥输入有效。用户修改其中任一项即清除旧结果，避免将旧结果误认为当前状态。
- 密钥只在本次测试请求中使用；测试失败和成功均不写入磁盘、不进入日志或 renderer snapshot。
- 技术细节默认折叠，经过脱敏后再展示；原始服务响应正文不直接呈现。

### 3.3 验收标准

- 每类结果都能区分，并给出用户可执行的下一步。
- 不提供模型列表的兼容服务可以继续手动配置；该路径不谎报密钥已验证。
- 编辑端点、模型或密钥后，上一条测试成功状态立即失效。
- 超时可结束等待并重试；错误信息、日志和页面均不包含提交的 API 密钥。

## 4. API 密钥管理升级

### 4.1 主连接密钥

- 将密钥管理从普通“保存配置”中拆成明确的动作：`替换密钥`、`移除已保存密钥`。若为兼容性保留当前复选框，也需在交互上突出清除动作并显示即时说明。
- 有已保存密钥且输入框为空时，显示“已在本机加密保存，当前请求会继续使用该密钥”，避免用户误以为留空会删除。
- 有已保存密钥且用户输入新值时，标明保存后将替换现有密钥；保存成功后清空输入框，只保留“密钥已更新”的状态，不回显密钥。
- 清除操作应有明确确认步骤，确认内容说明：后续云端请求将无法认证，除非重新填写密钥；清除后不可从 Yuki 恢复。
- 清除 API Key 与切换/保存端点分离。用户在编辑其他字段时，不应因误触一个复选框意外清掉密钥。
- 清除成功后更新状态并提示“已从本机移除”；失败时继续显示之前的已保存状态。
- 系统加密不可用时，不允许宣称密钥已安全保存；明确这是仅本次运行有效，并在离开或重启后提示需要重新输入。遵从现有加密策略，不新增明文持久化回退。

### 4.2 配置档案中的密钥

- 档案默认不包含 API 密钥，现有显式勾选加密保存的方式继续保留。
- 档案列表显示“含加密密钥”或“未保存密钥”，并提供辅助说明：前者可加载后直接使用，后者加载后需输入密钥。
- 档案已经含密钥、用户更新时取消“同时加密保存云端密钥”，应在保存前明确说明此操作会从档案中移除密钥；不影响当前主连接密钥。
- 更新档案时若勾选含密钥但输入框为空且当前端点有已保存密钥，明确会复用当前端点的主密钥；如没有可复用密钥则阻止保存并提示输入。
- 主连接密钥和档案密钥互相独立。清除主连接密钥不能悄悄清除档案内的密钥，反之亦然；在 UI 中说明清除作用范围。

### 4.3 验收标准

- 清除、替换和档案移除密钥各自有明确的成功/失败状态。
- 用户留空保存普通字段时，已保存密钥仍保留；用户主动清除后，配置快照只返回 `keyPresent=false`，不含密钥内容。
- 更新档案去掉密钥前有确认；仅影响选定档案。
- 任何情况下都不在输入框、配置快照、日志和错误提示中重新显示完整密钥。

## 5. 云端附件逐次发送确认

### 5.1 授权策略

保留当前“允许附件发送到云端”作为用户对当前端点的常驻授权，同时增加发送时的可见确认/检查步骤。设置授权是必要条件，但单独不足以隐藏本次即将发送的内容。

只有同时满足以下条件时才可向云端发送附件：

1. 当前所选端点与已保存并获授权的端点一致；
2. 当前云端附件授权为开启；
3. 本次发送确认中用户明确继续。

任一条件不满足，附件不进入云端请求；聊天文字可按用户操作继续发送，或由用户返回修改，界面需说明附件已被移除/未发送，不能静默丢弃。

### 5.2 发送前确认内容

确认面板放在发送动作附近，遵循当前工作台样式，不遮挡附件预览。显示：

- 接收方：服务商/配置名称；若无法识别品牌则显示端点主机名。
- 附件清单：文件名、类型、数量；图片发送处理后的图像（按需缩小至最长边 1536 像素），或按图片模式仅发送 OCR 文字。
- 派生内容：图片 OCR 文字、文档提取文本等实际会加入请求的内容。对长文本显示字符数和可展开预览，允许移除单项附件。
- 明确动作：“发送附件到 {host}”与“仅发送文字/返回检查”。按钮不得使用模糊的“继续”。
- 说明接收方由用户配置，Yuki 不代为审核其数据处理方式。

用户可以按当前端点选择“本次继续”或“记住对此端点的确认”。记住本次确认仍受端点绑定；端点变化、授权关闭或配置档案切换到其他端点时必须失效。产品若认为逐次确认成本过高，可以先只要求“每次显示检查面板”，将是否默认直接发送作为后续体验验证项；无论哪种模式，附件授权关闭时都不能发送。

### 5.3 取消与失败

- 在确认面板取消时，保持输入文字与附件，回到编辑状态。
- 用户选择只发文字时，明确附件未发送，并在本轮消息中提供可见标记；不得将附件文字偷偷拼进文本。
- 确认后请求失败时，附件保留在编辑器，可重试或移除；错误提示说明请求是否已发出存在不确定性，避免承诺对端未收到。
- 确认发生后若用户更换模型/端点，则使确认失效，重新展示接收方信息。

### 5.4 验收标准

- 授权关闭、端点未匹配或用户取消时，主进程请求体不包含图像和附件提取文本。
- 用户在点击发送前能检查实际发送的文件与提取内容，并能单项移除。
- 接收端点可见且与实际请求地址一致；切换端点后旧确认不复用。
- 产品帮助文档同步说明云端附件的可选授权和实际传输内容，修正当前《云端模型使用说明》中“附件只允许发送给本机模型”的旧描述。

## 6. 配置档案管理升级

### 6.1 保存与覆盖

- “保存为新档案”与“更新当前档案”使用不同的明确按钮/动作，避免根据当前选中状态隐式改变操作含义。
- 更新前显示档案名、端点、模型及是否包含加密密钥；如端点或模型发生变化，明确展示前后差异。
- 同名档案不静默覆盖：提示同名项并让用户选择加载/更新现有档案或修改名称。
- 档案名称去除首尾空格，限制长度，重名比较规则与系统现有规则一致。
- 加载档案只切换连接配置；如果档案不含密钥，加载后明确提示需要输入密钥。加载到不同端点会关闭附件授权，并显示该授权需要为新端点单独设置。
- 若当前主连接已有密钥，而用户加载一个不含密钥的档案，加载会清除当前主连接密钥；执行前明确提示并要求确认，避免无意丢失凭据。

### 6.2 删除

- 点击删除后弹出确认，展示档案名称、端点、模型，以及是否含加密密钥。
- 说明删除仅移除该档案；若该档案正是当前连接，不影响当前已加载连接和主连接密钥。
- 确认后才删除；取消不改变选中项。删除成功清空选中状态并给出撤销不可用的说明；删除失败保留档案和原选择。
- 删除包含密钥的档案时说明其中密钥随档案一起从本机配置移除，不影响当前连接副本。

### 6.3 验收标准

- 新建、更新、加载、删除都能辨认具体操作对象。
- 覆盖现有档案、删除档案、移除档案密钥都具备确认或清楚的二次选择。
- 档案详情/列表可以识别端点、模型和密钥是否存在；秘密本身从不显示。
- 加载无密钥档案、切换到新端点和删除当前档案时，状态提示与真实连接状态一致。

## 7. 隐私与实现要求

- Renderer 只持有用户正在输入的密钥，不持有已保存密钥的明文副本；沿用现有 preload/IPC 白名单和主进程验证。
- 主进程在发送请求前再次校验附件授权、端点一致性及本次确认票据，避免只依赖前端控制。
- 日志仅记录错误类别、HTTP 状态码和脱敏主机信息；不记录密钥、Authorization 请求头、附件原文或 OCR 全文。
- 状态变更采用失败回滚：磁盘写入失败时，UI 回到实际持久化状态，不显示成功。
- 未保存或测试中的密钥不应意外进入配置档案；用户勾选保存到档案时，提示其存储范围与清除方式。
- 保持云端附件授权绑定到端点；端点规范化后比较，避免尾斜杠等格式差异绕过/误触发状态。

## 8. 建议实施顺序

1. **连接测试状态结构化**：改动集中，先让错误与验证语义可靠。
2. **密钥清除/替换流程**：明确主密钥和档案密钥的作用范围，补齐显式确认。
3. **档案覆盖与删除确认**：基于统一的对话框/确认组件完成数据保护。
4. **附件发送前检查与主进程校验**：涉及消息组装、附件 OCR 文本和 IPC 请求边界，单独实施并覆盖拒绝路径。
5. 同步更新《云端模型使用说明.md》、`PRODUCT.md` 和必要的 UI 长期记忆；实现完成后再更新本方案状态与验收记录。

## 9. 本次文档的待确认产品取舍

- **附件确认频率：**建议先采用“授权后每次发送都显示内容检查面板”，可以逐项移除；用户确认后发送。请在实现前验证这一交互是否符合预期。
- **删除确认是否记住：**建议档案删除每次都确认，不提供“以后不再询问”。
- **无模型列表的测试措辞：**建议标记“连接可达、密钥未验证”，并允许保存手动模型 ID。

默认按上述建议实施；如产品验证结果不同，再更新此节与验收标准。

## 10. 实施状态（2026-11-13）

- **已实现连接反馈：**服务未提供模型列表、认证拒绝、网络失败、HTTP 状态错误、空模型列表和手动模型不匹配有区分提示；连接可达与密钥验证分开显示。编辑端点、模型或密钥会清除上次测试状态。
- **已实现密钥流程：**主连接密钥可单独确认移除；输入新密钥时提示将替换旧值；档案列表标出是否含密钥。更新档案展示名称、端点、模型和密钥保存状态的变更；含密钥档案取消密钥保存时随更新确认一并告知。
- **已实现附件检查：**云端发送前展示接收主机、模型、附件文件名/大小、图片发送模式、OCR/文档提取文字，并允许按项移除或只发送文字。复用对话上下文中的旧附件也会列入检查。
- **已实现主进程校验：**附件审核版本与附件内容摘要绑定；Electron 原生确认再次展示服务主机和模型；授权票据限时、单次使用并绑定端点/模型/附件集合。发送请求前再次检查授权和内容，端点/授权变化会使旧审核失效。
- **已同步说明：**`PRODUCT.md` 和《云端模型使用说明.md》已更新附件授权与测试流程。
- **构建：**TypeScript + Vite 生产构建通过。未运行测试套件；未能检查原生视觉，因当前 Electron 窗口最小化。测试、交互复验与 Electron 实机复验仍是后续验收项。
