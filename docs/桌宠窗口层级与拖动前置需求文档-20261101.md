# 桌宠窗口层级与拖动前置需求文档

**版本**：Draft 1.0 · 2026-11-01  
**状态**：待评审，本文是需求基线，不代表功能已实现。  
**范围**：桌宠原生窗口层级、拖动后的临时前置、总览中的层级设置。

## 1. 背景与问题

Yuki 平时应像桌面上的陪伴对象一样活动。当用户打开浏览器、编辑器或其他页面时，页面可以自然覆盖 Yuki，避免宠物持续挡住工作内容。用户主动把 Yuki 拖到当前页面上时，拖动动作表达了明确的查看或操作意图，此时 Yuki 应出现在当前前台页面之上。

当前代码已有 `Preferences.always_on_top`、Qt 原生窗口标志、拖动生命周期和巡逻前后层级切换。本需求要补齐统一的用户语义，并使“永久置顶”“允许被遮盖”“拖动临时前置”互不混淆。

## 2. 目标与非目标

### 2.1 目标

- 默认让普通应用窗口覆盖桌宠，桌宠仍可在桌面空白处活动。
- 用户开始一次有效拖动时，将桌宠提升到当前前台页面的上层。
- 在总览提供清楚、可恢复、可持久化的层级选择：`放置在最高层` 或 `允许被窗口遮盖`。
- 让层级变化在拖动、巡逻、窗口切换、专注、睡眠和重启后有稳定规则。
- 不改变桌宠的位置、物理、动作、素材、透明度、鼠标穿透和第三方窗口顺序。

### 2.2 非目标

- 不把桌宠强制显示在 Windows 锁屏、安全桌面、全屏独占程序或 UAC 提示之上。
- 不操作、重排、激活或修改第三方窗口的 z-order。
- 不新增自定义总览区块、页面编辑器、导航排序或独立的层级管理页面。
- 不改变现有巡逻穿窗的故事逻辑；巡逻临时层级必须服从本需求定义的用户偏好。

## 3. 核心概念

| 概念 | 定义 |
| --- | --- |
| 用户层级偏好 | 用户在总览选择的持久状态：`最高层` 或 `可被遮盖`。 |
| 普通桌面层 | `可被遮盖`偏好下的默认层级。普通应用窗口可以覆盖 Yuki。 |
| 临时前置层 | 一次有效手动拖动触发的短期状态。Yuki 位于拖动结束时的前台应用之上，但不等于永久置顶。 |
| 最高层 | `最高层`偏好下的持续状态。Yuki 尽量保持在普通窗口之上，直到用户切换回可被遮盖。 |
| 系统限制 | Windows 锁屏、安全桌面、受保护窗口、独占全屏等场景可能不允许或不应强制前置；此时显示实际可达状态。 |

## 4. 用户故事

1. 作为普通桌面用户，我打开页面后不希望 Yuki 挡住正文，因此页面可以覆盖 Yuki。
2. 作为想查看或移动 Yuki 的用户，我拖动 Yuki 到当前页面时，希望松手后仍能看见它，而不是被页面重新盖住。
3. 作为希望持续陪伴的用户，我可以在总览选择“放置在最高层”，让 Yuki 长期保持可见。
4. 作为专注工作的用户，我可以选择“允许被窗口遮盖”，并在需要时通过一次拖动临时把 Yuki 拉到前面。
5. 作为使用多显示器的用户，层级变化只影响 Yuki 所在屏幕，不把 Yuki 跳到其他屏幕或改变窗口位置。

## 5. 功能需求

### 5.1 默认与持久化

- 新安装或缺少该字段时，默认值为 `允许被窗口遮盖`。
- 设置保存到现有本机设置文件，与其他 `Preferences` 一起读写；不得新增第二套层级配置。
- 字段建议命名为 `window_layer_mode`，枚举值为 `occludable`、`always_on_top`。旧版 `always_on_top` 数据迁移规则：`true` 映射为 `always_on_top`，`false` 映射为 `occludable`；迁移后不再同时维护两个真值来源。
- 重启工作台和桌宠后恢复用户层级偏好；临时前置层不跨进程、不跨重启恢复。
- 保存失败时保留当前运行状态，给出现有统一错误提示，并允许重试。

### 5.2 普通活动与遮盖

- `occludable` 模式下，Yuki 可在桌面空白处正常待机、走动、停靠和执行既有动作。
- 当普通应用窗口覆盖 Yuki 时，不自动跳回最前、不闪烁、不反复重建窗口；状态可保持“被遮盖”。
- 被遮盖不等于隐藏：`visible` 仍为真，动作、作息和必要计时继续按既有规则运行；已有“隐藏雪”功能仍是独立语义。
- 切换到另一个普通应用或工作台时，不应因为焦点变化自动把 Yuki 提到最前。

### 5.3 手动拖动前置

- 只有用户按住 Yuki 并超过现有拖动阈值，形成有效左键拖动后，才触发临时前置；单击、双击、悬停和自动走动不触发。
- 拖动开始时立即进入临时前置层，保证拖动反馈不被当前窗口截断；拖动过程保持在当前前台普通窗口之上。
- 松手后保留临时前置，直到以下任一条件成立：
  - 用户激活另一个普通应用窗口；
  - 用户在工作台切换回“允许被窗口遮盖”；
  - Yuki 进入既有巡逻/穿窗层级切换流程；
  - Yuki 被隐藏、退出或系统进入不允许前置的桌面状态。
- 临时前置结束后恢复用户层级偏好，不写入 `always_on_top`/`window_layer_mode`。
- 如果用户在 `always_on_top` 模式拖动，拖动只刷新当前前置状态，不产生额外提示，也不改变偏好。
- 拖动失败、被取消、跨屏或窗口销毁时，必须清理临时前置标记并恢复可预测层级；不得留下“永远置顶”的隐性状态。

### 5.4 总览设置入口

- 在总览固定默认布局的“雪的此刻”或陪伴操作区域内，增加一项紧凑层级控制；不新增总览区块，不显示编辑拖柄。
- 控件标题：`桌面层级`。
- 控件采用二选一分段控件或单选组，选项文案固定为：
  - `放置在最高层`：持续显示在普通窗口上方。
  - `允许被窗口遮盖`：按普通桌面层活动，需要时可通过拖动临时置前。
- 当前选项必须有文字、选中态和键盘焦点，不能只用颜色区分。
- 说明文案：`平时允许页面盖住雪；主动拖动雪时，会暂时放到当前页面上方。`
- 工作台未连接桌宠时控件禁用，并沿用现有“等待桌宠连接”状态；浏览器预览显示能力限制，不伪造系统层级变化。
- 控件变更即时生效，成功后使用现有保存状态提示；失败保留原选项并显示可重试错误。

### 5.5 与已有行为的优先级

层级决策按以下优先级处理，从高到低：

1. Windows 系统安全桌面、锁屏和不允许前置的限制。
2. 用户有效拖动产生的临时前置。
3. 用户持久层级偏好。
4. 既有巡逻穿窗、窗口附着和图标互动的临时前后层级。
5. 普通桌面层默认行为。

巡逻结束、中断、睡眠、专注和拖动结束后，应回到用户偏好，而不是把巡逻临时状态写成永久设置。现有“专注时鼠标穿透”和“隐藏雪”不由本需求改义。

## 6. 状态模型

建议内部状态分为两个正交字段：

```text
window_layer_mode: occludable | always_on_top
temporary_foreground: false | true
```

有效层级计算：

| 用户偏好 | 临时前置 | 有效层级 |
| --- | --- | --- |
| occludable | false | 普通桌面层，可被窗口遮盖 |
| occludable | true | 当前前台普通窗口之上 |
| always_on_top | false | 最高层 |
| always_on_top | true | 最高层 |

状态事件至少包括：`drag_foreground_started`、`drag_foreground_ended`、`foreground_window_changed`、`layer_preference_changed`、`layer_restore_failed`。对外快照应能区分持久偏好和当前有效层级，供总览展示和诊断使用。

## 7. 接口与实现约束（供开发拆解）

- 继续使用现有 `set_preference` 命令和 `Preferences` 校验链；不新增绕过持久化的前端本地开关。
- 前端状态类型应同时暴露 `window_layer_mode` 与可选的运行态 `effective_layer`/`temporary_foreground`，避免用 `always_on_top` 一个布尔值承载两种语义。
- PySide6 原生窗口层级变更应集中在桌宠窗口层级控制处，统一处理 `WindowStaysOnTopHint`、Windows 原生前后层级和窗口重建后的恢复。
- 拖动代码在“超过现有拖动阈值”这一瞬间发起临时前置；不能等到松手才提升，否则拖动路径可能被遮盖。
- 前台窗口变化监听应只读取窗口层级/矩形等必要信息，不读取标题、正文、文件内容或用户输入。
- 工作台自身打开、聚焦、切页不应被误判为用户拖动前置，也不应自动改变永久偏好。
- 层级切换不得影响桌宠位置、透明度、尺寸、动画速度和鼠标命中区域。

## 8. 异常与边界条件

- **全屏/最大化应用**：允许系统自然遮盖；不强行破坏全屏体验。拖动若无法提升，显示一次非阻断提示或记录状态，不循环重试。
- **多显示器**：按 Yuki 当前所在屏幕处理；拖动跨屏时不改变用户偏好，松手后按新屏幕前台关系计算。
- **工作台前台**：桌宠仍可临时出现在工作台上方，但不遮挡工作台关键弹窗；Radix 对话框打开时遵循现有模态层级。
- **右键菜单/气泡**：沿用当前菜单和气泡的父子层级策略；不得因为气泡显示把永久偏好改为最高层。
- **巡逻出屏或后置**：巡逻专用的后置状态只在巡逻任务期间有效，任务结束必须恢复用户偏好。
- **设置重置**：恢复默认偏好时同时恢复为 `occludable`，并清除临时前置；需要在确认文案中明确包含“桌面层级”。
- **配置损坏/未知值**：按 `occludable` 安全回退，并记录现有存储错误机制可识别的信息。

## 9. 验收标准

### 功能

- [ ] 新安装默认可被普通窗口遮盖；普通页面覆盖 Yuki 时不闪回、不自动置顶。
- [ ] 从被遮盖状态有效拖动 Yuki，拖动开始立即可见，松手后仍位于当前前台页面之上。
- [ ] 激活另一个普通应用后，临时前置结束并恢复可被遮盖状态。
- [ ] 选择“放置在最高层”后，跨页面切换仍保持在普通窗口之上；切换回“允许被窗口遮盖”后立即恢复普通层。
- [ ] 单击、双击、自动走动、巡逻、菜单和气泡不会误触发永久置顶。
- [ ] 重启后恢复持久偏好，临时前置不残留。
- [ ] 恢复默认偏好后为可被遮盖，且临时前置已清除。

### 工作台与可用性

- [ ] 总览仍为固定默认布局，仅新增一个层级设置，不出现区块编辑入口。
- [ ] 三主题下选中、未选中、禁用、错误和保存中状态对比度一致。
- [ ] 键盘可聚焦并切换二选一控件；读屏可读出当前选项和说明。
- [ ] 桌宠未连接、浏览器预览、设置保存失败均有明确状态，不伪造成功。
- [ ] 紧凑窗口、展开窗口、Windows 125%/150% DPI 下文案不裁切、不溢出。

### 回归

- [ ] 现有拖动吸附、物理抛掷、窗口附着、图标互动、巡逻穿窗、专注陪伴、隐藏/显示和退出行为保持可用。
- [ ] 不改变第三方窗口 z-order，不读取窗口标题或正文。
- [ ] 减少动态设置下不增加额外动画；层级切换不引入闪烁或持续轮询。

## 10. 建议测试矩阵

| 场景 | 偏好 | 操作 | 预期 |
| --- | --- | --- | --- |
| 桌面空白 | 可被遮盖 | 打开浏览器覆盖 Yuki | Yuki 被遮盖，状态不变 |
| 当前浏览器 | 可被遮盖 | 拖动 Yuki 到浏览器内容区 | 拖动开始前置，松手仍在浏览器上方 |
| 切换编辑器 | 可被遮盖 | 激活另一个窗口 | 临时前置清除，Yuki 可被覆盖 |
| 多窗口 | 最高层 | 依次激活浏览器、编辑器、工作台 | Yuki 保持在普通窗口上方 |
| 工作台设置 | 任意 | 切换层级 | 即时生效，保存状态正确 |
| 重启 | 任意 | 关闭并重新打开 | 恢复持久偏好，不恢复临时前置 |
| 巡逻穿窗 | 可被遮盖 | 开始、结束、打断巡逻 | 巡逻后回到可被遮盖 |
| 专注/睡眠 | 任意 | 开始专注、进入睡眠、拖动唤醒 | 不改写层级偏好 |
| 多显示器 | 任意 | 跨屏拖动并切换窗口 | 只按当前屏幕处理，无跳屏 |

## 12. 待评审决策

以下默认按本文实现，除非评审时改写：

1. 默认值为“允许被窗口遮盖”，以符合桌宠平时不挡页面的目标。
2. 临时前置在前台应用变化时结束，不写入持久偏好。
3. “放置在最高层”只覆盖普通窗口，不覆盖锁屏、安全桌面和受保护全屏。
4. 总览使用现有设置行/分段控件，不新增总览区块或设置页。
