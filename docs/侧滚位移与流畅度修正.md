# Yuki 侧滚位移与连续采样修正

日期：2026-10-19。本次继续处理用户反馈的逐帧感和原地翻身，不生成新图片。

## 方向草案更新

用户随后指出头脚为翻滚轴，正向与反向侧滚应朝轴两侧移动，并进一步纠正之前的方向映射。现按最终约定：`lazy-roll-toward` 朝屏幕上方（y 减少）、`lazy-roll-away` 朝屏幕下方（y 增加），左右坐标保持不变。屏幕边缘可用空间不足时，路线会转向空间较充足的一侧，避免原地播放或越出工作区。暂不加入透视缩放。动作相位、停留和原素材均保留。

随后定位到闪烁来自 QPainter 的 `CompositionMode_Plus` 与逐帧透明度叠加：它会同时衰减目标缓冲，使半透明边缘亮度和 alpha 跳变。现改为对已预乘的 RGBA 像素通道做线性插值，避免 alpha 泵动。增加恒色半透明图的回归测试，跨连续亚帧检查颜色和 alpha 恒定。

实际绘制器与正式包分别验证正反向位移；相关播放器、待机、巡逻和插帧测试包含恒色半透明帧不会闪烁。方向预览见：[正向侧滚](验收资料/正向侧滚方向-20261019.gif)和[反向侧滚](验收资料/反向侧滚方向-20261019.gif)。闪烁修复直接消除相邻亚帧之间非预期的 alpha 与亮度波动；源姿势差异可能仍造成正常的轮廓变化。

## 查明的问题与修改

1. 原采样会把过渡进度取整到 25 张离线过渡图之一；如今在相邻过渡图之间做浮点采样，对预乘 RGBA 像素直接线性插值，减轻离散采样的跳动并消除绘制器叠加造成的 alpha/亮度脉冲。此处只混合两张相邻过渡图，源素材不匹配仍可能造成轮廓变化。
2. 侧滚曾对每个关键角度应用减速、停顿、再加速，产生“转一下、停一下”的节奏。现在滚动阶段连续经过各个角度，仅保留躺下、起步歇息和结束停留。
3. 普通待机侧滚此前没有窗口位移；巡逻侧滚有另一套按总时长缓动的横移，容易与姿势阶段错开。现已改为共用按实际翻滚角度计算的位移：先趴下再移动，正反滚方向相反，长停留时不滑行，完整循环之间不退回起点。最多移动约 150 个逻辑像素（随宠物尺寸缩放），并限制在工作区内。
4. 预读当前及后续两段贴图，后台解码；绘制和鼠标输入路径不等待磁盘。缓存继续有数量上限。

## 验证

- 119 项后端测试通过，覆盖播放器、插帧、随机待机、局部呼吸、巡逻、物理、点击、拖放与步行；最新边界回退逻辑另有 32 项定向测试通过。
- 33 项前端与 Electron 通信测试通过。
- 独立正式包的 18 项端到端检查通过，包含冻结后端播放侧滚时窗口沿头脚轴的垂直方向产生相反位移；界面控制台错误为 0，退出清理正常。
- 实际 Qt 绘制器导出双向侧滚各 279 帧：每段约 11.1 秒。最终方向下，toward 从 y=240 移至 y=82（-158 像素），away 移至 y=398（+158 像素），左右位置不变。
- 四组动作离屏绘制共 865 帧：单帧中位数约 3.14ms，95% 不超过约 6.24ms，最大约 9.25ms。这是隔离绘制耗时，不代表整台桌面运行的帧率保证。

## 启动

根目录 `start.bat` 通过 `start-electron.bat` 优先打开本次方向修正版：

`releases/electron/yuki-win32-x64-opposite-roll/yuki-win32-x64/yuki.exe`

当前运行的旧实例没有被强制结束；先在旧版菜单选择“保存并退出”，再运行根目录启动器。原连续性版本仍作为回退目录保留。

## 仍存在的素材边界

本次没有补画或重新生成素材，也没有建立 Live2D 模型。原始关键姿势在正面、侧面、背面间的遮挡变化较大，部分段落仍会出现轮廓变化或姿势切换感；25 张形变过渡不能等同于 25 张重新绘制的正确中间姿势。原先未通过形变筛选的 10 段仍回退原素材，未强行拉伸。进一步改善需要补充转面中间姿势，或制作可用的分层、多视角模型；生成新图仍须先给用户查看并确认。
