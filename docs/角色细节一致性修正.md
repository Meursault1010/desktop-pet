# Yuki 角色细节一致性修正（2026-10-19）

## 本次结果

用户认可母版复用样例后，已扩展并接入 29 组动作、331 个 PNG 帧（205 个不同姿势，其他为重复帧）。重建各组 atlas、poster、光流插帧及位置补偿，构建独立 Electron 发布包并验证通过。当前启动入口 `start-electron.bat` 优先选择 `releases/electron/yuki-win32-x64-hair-consistent/yuki-win32-x64/yuki.exe`。

这是第一轮头顶部位的一致性处理，不能视为全部状态已经统一或完全无痕切换。没有修改动作时序、侧滚位移、现有功能，也没有结束当前运行中的 Yuki 或提交 Git。

## 修正方法

母版使用 `console-v2/assets/living-idle/open.png` 的首个 256×256 单元，处理刘海、猫耳、雪花发饰及上部侧发的可复用纹理。

最初的完整头顶覆盖试验会影响原轮廓，部分姿势出现旧刘海边缘、抬手或趴姿脚部被遮盖。因此正式版采用保留原透明轮廓的局部纹理配准：以眼部与头顶锚点映射母版，再通过离线平滑光流配准原有头部细节，仅在限定头部区域替换冷色头发纹理。暖色皮肤、中央表情及下半身受到保护。

这与把完整正面头直接贴在各帧上不同：保留姿势原有轮廓和遮挡，改动更保守，也意味着原有几何差异仍可能存在。光流在素材构建时执行，不增加运行时图像修复负担。

覆盖：affection、afraid、angry、blink、celebrate、clicked、comb、curious、dragged、dress、eat、files、leap、prone-chin、prone-rest、read、reading-pose-1、reading-pose-3、sad、screen、shy、sit-neat、sit-relaxed、sit-swing、smile、stretch、tea、wait、yawn。其中部分组仅覆盖经审核适合的帧。

## 保留与限制

- 睡眠、侧背面阅读、两组慵懒侧滚、飞行及四方向碰撞的特殊视角或压缩造型保留原图，避免套用正面纹理。
- 等待中的侧面帧、工作侧面、部分伸展及低头帧保留；锚点不可靠或透视不适合的帧也未强行覆盖。
- 发尾、长后发的完整几何仍随原姿势保留，尚未统一其全部发束结构。
- 当前只修改动作库目录中的图像。实际拖拽、步行及图标附着使用的独立素材未在本轮修改；`dragged` 动作库帧不等同于交互拖拽素材。
- 后续需按侧面、背面、卧姿建立各自母版与遮挡，再逐组审核。新重绘素材仍应先展示给用户确认后接入，不能用正面覆盖掩盖视角差异。

## 复现与回退

构建脚本：`console-v2/build_character_consistency.py`。

`--stage` 根据检测与人工锚点生成候选并将审核状态重置为未通过；不得未经复核直接覆盖已审核 profile。`--apply` 要求已审核 profile，并校验原图、母版和候选哈希，保留精确原图备份后重建 atlas/poster。

随后依次执行：

```powershell
python console-v2/build_action_inbetweens.py
python console-v2/build_frame_alignment.py --write
```

插帧脚本不要仅传部分 `--actions` 后发布，否则会覆盖完整清单。修改原图后必须重建插帧与位置补偿。

原始帧和原始 atlas/poster 位于 `console-v2/action-work/character-consistency/originals/`，候选、人工锚点、审核配置及应用记录也在此工作目录。先前未通过的外部生成稿仅作为试验记录保存，未接入。本轮没有再次上传或生成图片。

正式包已独立输出，旧发布目录保留。回退可在保存退出后直接运行旧 `releases/electron/yuki-win32-x64-frame-aligned/yuki-win32-x64/yuki.exe`。源素材回退时，应恢复备份并重新构建插帧及位置补偿，不能只恢复 PNG。
