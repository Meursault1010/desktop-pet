# Yuki AI 助手对话界面综合改造方案

更新日期：2026-11-10  
状态：设计与实现方案，需在下一轮界面实施时按本文逐项验收。  
目标页面：工作台 → AI 助手 → 与雪对话。

## 1. 改造目标

以 Codex 当前对话工作区的**清晰层级、居中消息流、底部一体化输入框和按需呈现操作**为交互参考，继续使用 Yuki 的银雾、雪白、星夜主题及现有工作台结构。

改造后，用户应能一眼找到当前会话、历史会话、模型状态和输入位置；聊天正文拥有足够阅读宽度；附件、模型与发送操作集中在输入区；低频连接和隐私配置不挤占聊天空间。

本文借鉴布局与交互规律，不复制 Codex 的品牌、项目导航、权限控制、工具执行或其他 Yuki 尚不具备的能力。

## 2. 当前界面与 Codex 的差异

观察依据：2026-11-10 当前 Codex 桌面工作区截图、当时运行的 Yuki Electron 窗口，以及 Yuki 工作区源码。

| 维度 | 当前运行的 Yuki 窗口 | Codex 当前对话区 | 改造方向 |
|---|---|---|---|
| 页面结构 | 页面标题、与雪对话/模型连接子标签、会话和模型配置在同一内容页 | 独立的对话主区，导航和历史位于侧边 | 保留 Yuki 五项主导航；让聊天成为 AI 助手页主体 |
| 历史入口 | 历史会话较紧凑地出现在聊天卡片内，容易与消息区混在一起 | 历史和项目在左侧独立组织 | 宽屏使用 AI 页内历史侧栏；窄屏改为抽屉 |
| 消息流 | 用户与雪的消息使用更明显的角色和容器分组 | 用户消息突出显示；助手正文接近连续文档，动作较弱 | 用户消息采用柔和强调气泡；雪的长回复以正文排版为主 |
| 输入框 | 输入、附件、提示和发送操作分布于聊天区域底部，视觉上像普通表单 | 多行输入和底部操作整合为一块圆角面板 | 统一为固定在消息区底部的一体化 composer |
| 模型和连接 | 模型连接页、配置内容及聊天状态会占据同一页的显著空间 | 当前模型在输入框操作行中可见；低频细节按需访问 | 活跃模型放输入工具栏；服务地址和高级配置放入模型设置 |
| 状态反馈 | 成功连接信息可长期占据聊天区 | 运行状态贴近对话和输入动作 | 成功状态轻量呈现；错误、断连和重试清楚可见 |
| 产品能力 | 本地/云端模型、附件、会话持久化、重试、停止生成 | Codex 还提供项目、代码操作权限等开发工作流 | 只吸收通用聊天工作区模式，不添加不属于 Yuki 的操作 |

### 运行状态差异说明

检查时，当前 Electron 窗口仍呈现旧式子标签和页面内配置，而 `AssistantWorkspace.tsx` 已包含历史侧栏、精简工具栏和模型设置弹层等新结构。两者并非同一份可确认的运行视觉状态。实施前应先核对 Electron 当前加载的前端产物、窗口是否需要重启及构建目录，随后以实际运行窗口作为最终验收对象。不能仅凭源码或浏览器预览判定桌面版已更新。

## 3. 设计原则

1. **聊天优先**：消息流和输入框是页面主角；设置、隐私解释和连接诊断按需打开。
2. **保留 Yuki 身份**：延用工作台当前生效的 Quiet Orbit 样式、主题语义变量和组件，不建立第二套配色或控件规范。
3. **学习 Codex 的秩序，不复制开发工具**：Yuki 仍使用现有五项主导航；不增加项目树、权限等级、代码变更面板、语音或工具调用入口。
4. **渐进呈现**：常用操作直接可见；重命名、删除、清空、连接诊断等低频操作放在局部菜单、次级按钮或设置面板。
5. **状态必须真实**：本地/云端、模型连接、附件处理和持久化状态均来自现有宿主能力；演示环境明确标示不可用，不显示虚构状态。
6. **保留能力与数据**：不改变会话存储格式、用户偏好、附件安全规则、提示词流程或模型连接逻辑。

## 4. 目标页面结构

```text
Yuki 工作台主壳层（标题栏 + 固定主导航）
└─ AI 助手
   └─ 对话工作区
      ├─ 历史侧栏（宽屏常驻 / 窄屏抽屉）
      │  ├─ 新对话
      │  ├─ 最近会话列表
      │  └─ 会话行操作：重命名、删除
      └─ 当前会话
         ├─ 会话工具栏：历史入口、会话名、连接/模型摘要、设置
         ├─ 可滚动消息流（正文列与输入框同宽）
         └─ 固定输入面板
            ├─ 多行输入区
            └─ 附件、输入提示、模型/思考选项、发送/停止

模型设置：通过工具栏入口打开弹层或侧面板
```

AI 页外层仍遵守 Yuki 工作台的标题、主导航和内容滚动结构。不要再为聊天页复制一套 Codex 左侧全局导航。

## 5. 区域规格与交互

### 5.1 历史侧栏

- 宽屏侧栏独立于消息流；基于现有源码的约 224 px 宽度作为起点，按 880 px 最小窗口检查是否挤压正文。
- 窄屏改为抽屉，使用明显的历史按钮、遮罩关闭和 Escape 关闭；打开后焦点可进入会话列表，关闭后焦点返回触发按钮。
- 顶部提供“新对话”。会话行展示标题、更新时间或消息数；当前会话有选中态。
- 重命名和删除属于会话级操作，采用可见标签或明确的无障碍名称。删除/清空按既有交互规则确认并可恢复策略不擅自变化。
- 若会话数量未来增长到明显难以浏览，再另行评估搜索和按日期分组；本次不虚构或扩展需求。
- 空列表、存储不可用、读取中和读取失败分别显示真实状态。

### 5.2 会话工具栏

- 显示当前会话标题；标题过长时截断，完整名称可通过可访问名称或提示获取。
- 连接状态使用短文字和语义状态标识；不要只靠颜色传达。
- 当前活跃模型应便于识别。若模型选择移入 composer，工具栏不再重复一份可操作模型下拉，避免两处状态不同步。
- “模型设置”负责连接地址、提供方、本地/云端选择、对话保存和附件隐私等低频设置。
- “新对话”可以放在历史侧栏顶部；窄屏也可在工具栏保留清晰的新建入口，但避免重复按钮同时争主次。

### 5.3 消息流

- 使用单列阅读布局。正文宽度建议从现有 780 px 上限开始，在桌面上保持居中；输入框与消息正文对齐。
- 用户消息靠右呈现为轻量气泡，使用现有蓝色语义强调；长消息宽度受限并自然换行。
- 雪的回复以连续文本为主，不为整篇回答套大卡片。保留段落、标题、列表、链接和代码块的可读排版。
- “你/雪”角色标识不应比消息正文更抢眼；头像或角色素材按既有产品约束使用，不新造角色图。
- 复制、重新生成、删除等操作在悬停和键盘聚焦时可访问；触屏场景不依赖悬停。
- 空状态可保留雪的轻量陪伴感和建议问题，但不盖过输入框，也不将建议问题伪装成真实对话。
- 长会话保持滚动位置稳定。新消息到达时，如果用户已在底部则跟随；若正在查看历史，不强制拉回底部，并提供回到底部入口。

### 5.4 一体化输入框（本次视觉重点）

目标形态参考 Codex 的圆角输入面板：同一表面承载文本和底部操作，但使用 Yuki 当前的表面、边界、强调色和圆角令牌。

```text
┌─────────────────────────────────────────────┐
│ 想对雪说些什么？                             │
│                                             │
│ + 附件     Enter 发送 · Shift+Enter 换行     │
│             [当前模型 ▾] [思考 ▾] [发送/停止] │
└─────────────────────────────────────────────┘
```

- 文本区位于上方，支持多行增长并设置合理最大高度；超过后在输入区内部滚动，不推走整页布局。
- 底部工具行左侧放附件入口及必要提示，右侧放当前模型、适用时的思考选项和发送/停止按钮。
- 当前实现中仅 HTTPS 模型配置显示思考程度选择；未来仍需根据实际模型支持情况决定是否显示，不能将其扩成所有模型通用能力。
- 附件选择后在输入面板上方或内部显示文件名、类型、大小和移除入口；继续遵守每条最多 4 个、单个不超过 10 MB 的既有约束。
- 输入框 focus、禁用、发送中、附件读取中和错误状态应可区分；发送按钮在草稿/附件为空、模型不可用或附件处理中时按现有规则禁用。
- 生成期间显示停止按钮；停止后恢复发送状态，不清除草稿或附件。
- 云端模型的附件隐私提醒应在设置和必要的选择时机清晰说明，不在每条消息下重复大段说明。
- 输入法合成期间 Enter 不得发送；Enter 和 Shift+Enter 的现有键盘规则保持一致。
- 不新增麦克风、权限级别、网页搜索或工具调用按钮，除非产品能力另有明确实现与确认。

### 5.5 模型与隐私设置

将低频配置收纳在对话页可达的设置弹层/面板中，内容分组如下：

1. **服务与模型**：本地/云端提供方、服务地址、模型选择、重新连接和连接结果。
2. **对话记录**：是否跨运行保存、当前保存状态、用户可执行的清理操作（若已有）。
3. **附件与数据**：本地 OCR、文档提取限制、附件发往云端的条件和附件仅本次运行保留规则。
4. **诊断与限制**：真实未启用项目或宿主不支持提示；没有实现的功能不得显示成可配置开关。

弹层须支持 Escape、关闭按钮、合理焦点管理、内部滚动和窄屏全宽适配。只保留用户作决定所需的信息，详细解释分段呈现，避免一屏堆叠长说明。

## 6. 状态与文案要求

| 状态 | 界面表现 | 规则 |
|---|---|---|
| 尚未连接 | 模型未连接；输入框提示先连接模型 | 明确引导去模型设置，不伪装可发送 |
| 正在连接 | 连接按钮和状态文字显示进行中 | 防重复点击；失败时说明原因和下一步 |
| 已连接 | 轻量状态标识和当前模型名称 | 成功提示不长期占据消息流 |
| 正在生成 | 助手回复进行中，发送键变停止 | 用户仍能看见生成状态；停止操作有效 |
| 请求失败 | 错误位于相关消息/输入附近，提供重试 | 保留原草稿及附件；说明重试将发送/替换什么 |
| 附件读取中 | 文件区域显示读取状态 | 读取完成前不可重复发送；失败可移除或重试 |
| 无会话记录 | 侧栏为空态和新对话入口 | 不伪造历史 |
| 浏览器预览不支持宿主能力 | 明确显示“预览中不可用”或对应限制 | 不显示“保存在本机”等虚假能力状态 |
| 持久化关闭 | 明确为仅本次运行 | 重启后数据行为与文案一致 |

## 7. 视觉规范与窗口适配

- 延用 `workbench-v3.css` 的 Quiet Orbit 最终覆盖层和 DESIGN.md 的共享主题语义；三主题只改变色彩与材质，不改变布局和状态含义。
- 继续用功能无衬线字体；Georgia 仅用于现有品牌/诗句语境，不用于模型、状态和正文。
- 圆角、间距、边线和按钮状态沿用现有工作台令牌。composer 可比普通字段更有整体感，但不要改造成厚重玻璃、强光晕或霓虹卡片。
- 1150 px 以下历史侧栏转抽屉；700 px 以下收紧工具栏和输入工具行。若原生 Electron 最小宽度为 880 px，需以原生尺寸检查，不能只依赖窄屏浏览器结果。
- 小窗口下模型名称、会话标题可截断，但附件、发送/停止、历史和设置入口必须仍可访问。
- 检查 125%、150% Windows 缩放；正文不能因适配而过小，滚动条不能遮住输入区。
- 尊重系统和应用减少动态偏好；抽屉和弹层使用短促位移/透明度变化，不影响立即操作。

## 8. 实现范围与代码定位

主要实现位置：

- `console-v2/frontend/src/components/AssistantWorkspace.tsx`：消息流、会话历史、工具栏、composer、设置弹层及现有状态逻辑。
- `console-v2/frontend/src/workbench-v3.css`：AI 助手最终样式覆盖及响应式规则。
- 若消息排版、附件预览或 markdown 渲染由同类组件承载，优先复用现有实现；不要为视觉改造重写模型请求或宿主 IPC。

源码现状已存在的改造基础：历史侧栏/窄屏抽屉、精简会话工具栏、居中消息宽度、雪回复正文式排版、模型设置弹层。需评估和补齐的重点：

- 当前运行 Electron 界面和源码产物不同步，先校准实际加载版本。
- 让 composer 成为更明确的一体化操作面板；模型选择是否从顶部移入底部工具行，应保证唯一、连贯、适配窄窗口。
- 按 Codex 阅读节奏进一步弱化雪的回复容器与冗长连接成功提示。
- 将真实连接、附件、持久化状态完整接入新布局并进行宿主验证。

## 9. 实施阶段

### 阶段一：运行版本核对

- 对照源代码、构建输出、Electron 加载路径和当前工作区窗口。
- 确认改造版在真实 Electron 窗口呈现，记录基准截图和窗口尺寸。
- 若窗口仍显示旧版，先处理运行版本/重载流程，不在两套 UI 上重复开发。

### 阶段二：对话区和 composer

- 保持消息正文最大宽度与 composer 对齐。
- 完善用户气泡、助手连续正文、消息操作和长会话滚动。
- 整合附件、模型、思考选项及发送/停止操作；移除重复的模型入口。

### 阶段三：状态和设置

- 逐一连接真实宿主状态：连接、模型、持久化、附件读取和错误/重试。
- 精简设置内容层级，确认隐私说明在本地与云端模型下均准确。
- 校验空会话、无模型、断连、发送失败、停止生成和浏览器预览状态。

### 阶段四：窗口和主题验收

- 在原生最小尺寸、常用窗口和展开窗口检查布局。
- 验收银雾、雪白、星夜主题、125%/150% DPI、键盘和中文输入法。
- 按改动范围执行构建与必要的交互验证；不以旧截图或规划文档替代本次结果。

## 10. 验收清单

### 结构与视觉

- [ ] 对话主区是页面焦点，标题和工具栏没有多余重复入口。
- [ ] 宽屏历史侧栏和窄屏抽屉可正常切换；会话标题与消息列表不互相挤压。
- [ ] 消息正文和 composer 居中对齐，正文宽度舒适；用户与助手层级清晰。
- [ ] 输入面板统一承载输入和底部操作；状态变化不会造成页面跳动。
- [ ] 设置弹层滚动、关闭、Escape 和焦点返回正常。

### 功能与数据

- [ ] 新建、切换、重命名、删除和清空会话行为与原实现一致。
- [ ] 发送、停止、重试、重新生成、复制、删除消息可用。
- [ ] 附件类型、数量、大小限制及本地/云端发送规则保持一致。
- [ ] 草稿、附件、会话记录及持久化继续服从既有产品规则。
- [ ] 连接失败和宿主不支持状态有真实说明；预览不显示虚假模型或本机存储状态。

### 输入、可访问性与适配

- [ ] 中文输入法组合期间 Enter 不发送；Enter 发送、Shift+Enter 换行。
- [ ] 所有图标按钮有名称；键盘焦点清楚；触屏不依赖 hover。
- [ ] 最小原生窗口及常用尺寸下输入区始终可见、可操作。
- [ ] 三主题、125%/150% DPI 和减少动态偏好均通过目视/交互检查。

## 11. 本次明确不包含

- 不增加联网搜索、语音输入、工具调用、Codex 式权限模式或代码工作区。
- 不修改模型协议、会话数据格式、宿主 IPC、附件解析规则、桌宠行为或一级导航。
- 不重做整个 Yuki 工作台品牌视觉，不复制 Codex 的黑色主题、项目侧栏和开发者功能。
- 不因改造顺手加入历史搜索、会话标签或其他未经确认的产品能力。
