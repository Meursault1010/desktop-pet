# Yuki 图片与文档识别（2026-10-20）

先启动 Bionic 本地模型服务，再通过项目根目录 start.bat 启动新版 Yuki。在工作台「AI 助手」输入框左下角点击回形针，选择截图或文字图片，待附件显示「OCR 已提取 … 字符」后，输入识别、翻译或总结要求并发送。旧版请先保存并退出，再启动新版。

支持 PNG、JPEG、WebP、PDF、DOCX 和 UTF-8 TXT/MD/CSV/JSON/LOG；每条最多4个，每个最多10MB，图片最多2400万像素。图片预览最长边缩至1536像素，OCR 使用原图；每个附件最多提取18000字符，当前请求附件文字合计最多24000字符。扫描PDF没有文字层时请转为图片。

附件内容只发送到配置的本机模型接口，不会发送云端。附件及对话只在本次运行内存中保存，最多缓存24个附件，较早附件失效需重新添加。文档中的命令不作为系统指令执行。

当前链路：图片 → 本地 RapidOCR / ONNX Runtime CPU 识别 → 提取文字 → 当前 Qwen 分析、翻译或总结。Bionic 接口为 http://127.0.0.1:1235/v1，模型为 qwen3.8-4b-distill；实测该部署拒绝直接图片输入，因此使用 OCR 提取文字，不更换原模型。OCR 通过独立子进程执行，不占模型显存。透明 PNG 先合成到白底识别；无文字图片明确提示，不让模型猜测。该功能只识别文字，不提供照片物品或场景理解，手写和复杂排版可能不准确。

发布版已内置 OCR 程序、识别模型和运行依赖，无须另装 Python 或下载 OCR 模型，整个 OCR 目录约237 MiB。请保持完整发布目录，不要单独移动 yuki.exe。开发构建使用 build-ocr.ps1（已安装依赖可加 -SkipInstall）；build-electron.ps1 会自动执行 OCR 构建，并复制到 resources/ocr。已测试依赖锁定于 tools/ocr/requirements-lock.txt。

验证：48项单元测试通过，生产构建通过，最终发布版21项运行检查通过。真实发布版读出了中英文报错截图，透明文字图片识别通过，空白图片被正确拒绝；当前 Qwen 将英文句子翻译为「你的下载已完成。」测试图片 OCR 约2.8秒，速度因图片和电脑而异。验收资料见 docs/验收资料/ocr-20261020，packaged-verification.json 为实际 OCR→Qwen 记录，final-smoke.json 为完整发布版运行检查。
