## 日常启动与开发

日常仍使用桌面安装目录的 `start.bat`。开发源码没有复制安装版 `.venv`，不要把虚拟环境目录直接搬家。需要运行开发副本时，在 `console-v2/` 执行 `install.bat` 创建独立环境后，再使用其中的 `start.bat`；先退出当前桌面版，避免共用设置或单实例造成混淆。

若仅运行测试，可调用现有 PySide6 Python，以 `console-v2/` 为工作目录。测试使用临时设置与离屏 Qt，不应修改个人设置：

```powershell
$env:QT_QPA_PLATFORM='offscreen'
$env:PYTHONDONTWRITEBYTECODE='1'
& 'C:\Users\meursault\Desktop\desktop-pet\.venv\Scripts\python.exe' -B -m unittest discover -p 'test_*.py'
```

前端测试，以 `console-v2/frontend/` 为工作目录：

```powershell
node --experimental-strip-types --test tests/actionAssets.test.mjs tests/actionTimeline.test.mjs tests/commandQueue.test.mjs
npm.cmd run build
```

测试和构建本身不部署桌面安装目录，也不启动可见宠物。`npm run build` 更新前端 dist；已有 Rust release 中间产物保留在原路径，应在正式交付前重新构建。

Tauri 构建可从 `console-v2/` 使用现有 `build_frontend.ps1 -ToolchainDirectory .toolchain`；该脚本会执行 `npm ci`、Tauri 构建并写入本开发副本的 `app/`。使用前检查依赖与网络条件。不要在桌面版仍运行时覆盖其 EXE。

## 继续维护时的边界

先查代码与运行目录，再读历史文档。`console-v2/` 内部分主题文档仍含早期路径、四姿势或旧自动依靠开关描述；当前事实以总结、代码和测试为准。本次未全盘改写历史过程记录。

仅修改 Python 时通常重启后端即可；React、catalog 或预览资源变化需要同步 `frontend/public/actions/` 并重编 EXE。不要仅改源码却继续交付旧 EXE。

不要改变图标遮裙与头发前景规则，不要重置个人设置，不要将 stdout 用作日志，不要把大动作整图淡化当作补帧。自主移动继续使用行走动画；手动即时吸附不进入行走阶段。

旧 `deploy_*.ps1`、`package_*.py`、归档安装脚本和生图脚本可能包含旧绝对路径、旧哈希保护或外部服务请求，保留仅便于追溯，运行前必须重新核对。没有本次上传授权时，不因脚本存在而自动生成图片或上传素材。
