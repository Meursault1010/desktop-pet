# Yuki 工作台 UI 设计文档：Refero 研究版

版本：设计提案 v2.0  
日期：2026-10-20（Asia/Shanghai）  
状态：供用户确认，尚未应用于正式程序。  
范围：Electron 工作台、宠物右键菜单、可调整面板、自定义页面、视觉与交互规范。

## 1. 设计结论

Yuki 应当是一间安静、精密但有生命的桌面工作室。界面用冰蓝、银灰和白色建立冷静秩序；角色本身承担亲近感；微弱的星尘只提供空间，不抢夺注意力。丰富来自真实的角色状态、恰当的信息密度和细腻反馈，不靠增加光效与卡片数量。

主方向命名为「静夜工作室 / Quiet orbit」。这只是内部设计概念，不要求在界面反复展示英文名。

本提案延续用户确定的五个一级栏目：总览、角色、AI 助手、工具、设置。既有角色资产、动作逻辑和 Electron 架构继续作为基础。需要审批的是下一版视觉稿及交互原型，而不是现在就替换程序。

文档中「建议」「目标」「待实现」均为本项目提案；不等于功能已经存在，也不等于参考站点采用了完全相同实现。

## 2. 对现有预览的具体修订

当前总览与右键图是第一轮静态概念稿，用户尚未确认。它们说明了大方向，但还需处理以下问题：

1. 总览几乎每块都有相同边框、标题栏与菜单，容易变成通用仪表盘。新稿只对真正可独立调整的面板使用容器，面板内部优先用行与留白，不套娃。
2. 角色区虽突出，但「雪，在身边」与说明占用较多面积。保留角色尺度，收短文案，把当前状态、陪伴模式和下一步意图排成一条清楚关系。
3. 时钟、天气、模式、系统指标的权重过于接近。新稿以雪的此刻为第一层，以时间与模式为第二层，CPU 等后台状态降为摘要。
4. 今日足迹柱状图目前只是视觉示例。正式稿应改为有数据依据的活动时间线；没有采集数据时保留真实空态，不用随机柱形填满。
5. 预览默认展示布局编辑状态。下一版主图先展示正常使用，另图展示拖动、缩放与添加区块，避免误以为所有拖柄常驻。
6. 右键菜单有较多空白、退出行距离较远。新稿收紧为内容驱动高度，保持聊天输入舒适，退出作为底部独立一行。
7. 深色元数据有些偏灰暗。新版将可阅读文字与装饰弱线严格区分，淡星点不能决定正文对比。
8. 「健康」和「专注」不应被误解成互斥的两种配置：陪伴强度与健康提醒是独立维度。专注期间健康提醒的呈现方式可单独设置。

## 3. 产品气质与设计原则

### 3.1 冷静与亲近的分工

- 界面：直观、低噪声、有秩序，像精密软件工作区。
- Yuki：人物比例完整、细节稳定，呼吸、睡眠和回应自然。
- 文案：功能名称直白；少量英文题记有艺术气息，但不妨碍操作。
- 动态：角色负责生命感，界面负责解释变化，星辰负责背景深度。

### 3.2 不采用的视觉习惯

不用彩虹图表、霓虹线框、玻璃叠玻璃、粒子雨、全屏星云、扫描光、装饰 HUD、巨型渐变标题、重复的图标色块、无依据的统计数字。也不用无处不在的胶囊、每卡同款阴影、每页欢迎横幅或滚动时所有元素依次飞入。

保留蓝白银不意味着全部涂蓝。绝大多数表面是低饱和冷灰，蓝色用在关键交互与角色的自然色彩上。成功、警告、错误仍需要独立语义，不能为了统一配色全部改成蓝色。

### 3.3 理论与实际规则

| 原则 | 具体规则 | 如何验证 |
|---|---|---|
| 渐进披露 | 总览只给摘要；参数在专页；高级连接项默认折叠 | 从总览找到聊天、模式与隐藏宠物无需读说明 |
| 选择负担 | 一级固定五栏；每个任务只强调一个下一步 | 首屏没有两颗同义主按钮 |
| 接近与共同区域 | 状态贴近对应对象；天气地点在天气内；模型状态靠近聊天 | 离线时不会误以为另一模型也离线 |
| 直接操纵 | 拖动有占位，缩放即时预览，取消可还原 | 用户能预测放下后的布局 |
| 可逆性 | 移除面板不删除业务数据；取消编辑恢复快照 | 移除、撤销、重启后状态一致 |
| 状态可见 | 当前动作、触发原因、连接中与保存失败有文字 | 不凭圆点颜色猜测状态 |
| 空间恒常 | 翻页后主要操作位置稳定，菜单靠近触发位置 | 不发生搜索按钮、发送按钮随状态跳位 |
| 注意力预算 | 专注时压低非必要提示与背景动效 | 计时期间不会连续弹庆祝动画 |

这些是设计假设与验收依据，不能冒称已经过用户实验验证。

## 4. 信息架构与导航

    工作台
    ├─ 总览：默认总览、用户自定义页
    ├─ 角色：音乐互动 / 动作 / 外观 / 行为逻辑
    ├─ AI 助手：本地模型 / 云端 API
    ├─ 工具：时间管理 / 剪贴板 / 待办事项
    │        划线翻译作为建议第四项，待确认
    └─ 设置：通用 / 主题与动态 / 通知 / 快捷键 / 长期记忆 / 隐私与数据

侧栏只放五个一级入口，有文字，不用图标猜功能。一级页内部使用横向子页签；设置可用局部分类列。导航记住上次子页、筛选、滚动与未发送草稿。自定义页面归属总览，不作为第六个一级栏目。

顶栏保留产品名、当前位置与必要的窗口控制。没有真实用途时，不添加账户头像、通知铃铛、搜索或升级按钮。窗口拖动区域与输入、菜单、按钮严格分开。

## 5. 页面布局规范

### 5.1 总览：先看雪，再看今天

首要问题：「雪现在怎么样，我是否需要做什么？」

建议默认采用不等宽的三列关系，而不是所有内容同样大。宽窗口里，角色状态与今日足迹共享宽主区，时间与陪伴位于侧区。后台系统摘要放到更安静的位置。窄窗口按内容优先级顺序重排。

    [五栏导航]  总览                    [自定义布局]
                 默认总览   我的工作区  +
                 ┌──────────────────┬──────────────┐
                 │ 雪的此刻          │ 时间 / 天气   │
                 │ 完整角色 + 状态   │              │
                 │ 两个快捷操作      ├──────────────┤
                 │                  │ 陪伴 / 专注   │
                 ├──────────────────┼──────────────┤
                 │ 今日足迹 / 总结   │ 正在播放      │
                 ├──────────────────┴──────────────┤
                 │ 系统摘要与近期事件                 │
                 └─────────────────────────────────┘

- 雪的此刻：当前动作、状态原因与下一步意图。下一步若尚未调度，写「暂未安排」，不伪造精确倒计时。显示隐藏、移到右下角使用两个稳定位置的操作。
- 陪伴：可提供日常、安静、专注等强度选择；健康提醒独立开关。模式卡展示生效范围，例如「暂停主动闲聊，保留待办提醒」。最终模式名随现有实现核对。
- 时间天气：时钟使用等宽数字特性，避免跳动；地点、更新时间与失败状态可查。没有地点或连接时明确引导设置。
- 音乐：真实曲目、来源和播放状态；无曲目时写「当前没有播放内容」。没有媒体会话时，不保留会自行起伏的假波形。
- 系统：CPU、内存、电源、自启、U 盘采用数据行。无权限、未连接、未采集、值为零是四种不同状态。
- 今日足迹：先显示用户授权范围内的时长、专注与任务结果。详细时间线默认 4–6 条，可查看全部。总结标明数据来源、覆盖时段与是否由模型生成。
- 下载和编译事件需要真实事件接入；目录稳定性推断应标记「推测完成」，不能等同确定结果。

默认总览不把全部功能塞满首屏。1440×900 下必须看见雪的状态、陪伴入口、时间天气、媒体和今日摘要；较低优先级事件可在首屏底部露出标题并自然滚动。自定义布局允许用户重新排序。

### 5.2 角色：预览舞台与参数检查区

角色页面不复制总览布局。中间展示真实 Yuki，右侧 280–320px 检查区提供对应参数；窄窗检查区移到舞台下方。

| 子页 | 主体 | 操作与状态 |
|---|---|---|
| 音乐互动 | 曲目、音频输入状态、小范围真实频谱、角色预览 | 开启互动、灵敏度、反应频率、安静限制；无音源有说明 |
| 动作 | 分类浏览＋大预览＋一条真实时间轴 | 搜索、分类、预览、在桌面播放；清楚区分两个播放目标 |
| 外观 | 同一角色的实时预览 | 服装造型、文字字体、气泡样式、尺寸；仅列实际可用资产 |
| 行为逻辑 | 现在 / 原因 / 下一步 / 近期事件 | 每条规则显示是否启用和覆盖关系；技术详情折叠 |

动作分类至少可表达：生成与消失、站立待机、坐下待机、趴着待机、睡眠、移动、拖拽与点击、抛出与碰撞、附着、音乐互动。以实际 catalog 为准，不凭设计文案编造存在的动作。缩略图只按需播放，避免几十个 GIF 同时运行。

行为逻辑页的重要区分：当前实际状态来自桌宠运行时；计划动作来自调度器；可能动作只是规则范围。三者不能混成一句「接下来一定会」。用户已经提出过附着规则调整，重做 UI 时必须展示目前运行规则，不能顺手恢复旧版自动附着。

### 5.3 AI 助手：对话是主体，配置是附属

- 本地模型子页：消息流占中心，输入框固定在消息区底部。模型名、连接状态、支持能力以简洁一行显示，可展开连接详情。
- 首次配置：给出地址与模型选择，不用复杂诊断墙压住输入。测试连接成功和模型推理成功分开呈现。
- 云端 API 子页：地址、Key、模型名为基础表单；兼容协议、超时、上下文等高级项按需展开。Key 掩码、可替换，避免在界面和日志回显完整值。
- 当前是本地还是云端必须始终可辨；本地失败不能暗中改用收费云端。
- 附件区显示文件名、类型、处理进度和取消。OCR 文字提取、PDF/DOCX 解析与多模态视觉能力分别标明。
- 输入支持中文组合输入；Enter 发送遵守 composition 状态；Shift+Enter 换行。加载时可停止，失败保留草稿与附件。
- 长回答保持自然阅读宽度约 640–780px，代码可横向滚动；不要为聊天气泡铺满星点或强对比背景。
- 长期记忆以可查看、修改、删除的项目展示；模型推测与用户确认事实分开。

### 5.4 工具：列表、详情和清楚结果

时间管理：活动计时是焦点，可显示与下一事项相关的信息。时间盘不是必需装饰；开始、暂停、继续、结束的按钮随状态明确切换。健康提醒与专注计时避免重复打扰。

剪贴板：保持现有十条边界。左侧紧凑摘要列表，选中项在右侧显示完整内容、时间、复制与删除。小窗口改为列表后进入详情。内容类型和保留策略依现有实现，不从参考截图推导新能力。暂停记录与清空历史应容易找到。

待办：顶部一行新增，列表显示名称、到期时间和完成状态。选中后侧面编辑说明、提醒与重复选项。未实现的重复提醒不能以可点击控件假装存在。提醒弹窗说明事项和时间，支持稍后提醒，不和宠物自言自语混用。

划线翻译：建议作为工具第四子页，复用现有功能入口。选区、复制备用、OCR 框选三种来源明确区分；浮窗默认紧凑，原文按需展开。是否正式作为第四栏仍待确认。

### 5.5 设置：可扫描的分组行

设置内容采用标题、简短说明、控件和值对齐的连续行，减少每项独立卡片。通用、主题动态、通知、快捷键、记忆和隐私有明确层级。

轻量切换可即时保存并显示结果，失败回滚到实际值；多字段连接与记忆编辑使用明确保存和取消。不要使用一个统一「保存」同时控制不同持久化机制。

快捷键必须显示当前组合、冲突与注册失败；不能显示已保存却实际无法全局注册。长期记忆区提供人物设定、用户确认信息、来源与更新时间；危险删除保留明确确认。

## 6. Adobe 式面板与自定义页面

这是工作区交互提案，来自用户要求，不是把网页做成任意漂浮窗口。

### 6.1 两种操作模式

正常模式：布局锁定，标题栏安静，无常驻拖柄与缩放角。每块的必要业务控件仍可直接使用。「自定义布局」是统一入口。

编辑模式：显示拖柄、选择框、角部缩放、添加区块和完成。编辑的是布局草稿；完成提交，取消或 Esc 恢复进入编辑时的快照。未完成的布局不要半途覆盖正式布局。

拖动只从标题栏或拖柄开始，文本选择、输入、滑块、滚动和媒体控制不会触发拖动。面板跟手，目标位置有等尺寸占位，其他面板稳定让位。鼠标离开窗口、pointercancel、DPI 切换或失焦时可结束操作并恢复一致状态。

### 6.2 栅格、停靠与缩放

- 首版采用有边界的工作区栅格：宽窗 12 列、中窗 8 列、窄窗 4 列，间隙建议 16px。先实现可靠的移动、缩放、折叠与隐藏。
- 标题栏建议 36px，拖柄可见图形小但命中区至少 28px；缩放角命中区至少 20–24px。
- 指向目标时才显示吸附指示；释放后吸附，不添加弹簧过冲。只预览相邻候选，不显示满屏辅助线。
- 面板有最小尺寸和 compact / normal / expanded 内容策略。尺寸不足时减少摘要行或切换排列，禁止把文字与人物整体缩小挤入。
- 首版不默认承诺 Adobe 的全部能力。标签分组、任意方向停靠、独立浮窗作为后续阶段，需单独验证焦点、层级和保存规则。
- 键盘可替代：面板菜单提供前移、后移和尺寸预设；可选移动模式中方向键调整、Enter 确认、Esc 取消。

### 6.3 自定义页面与区块库

总览页签旁加号用于新建自定义页面。支持命名、重排、复制、重命名、删除。删除的是页面布局，不是聊天、待办、剪贴板或动作资产。默认总览保留恢复入口。

区块库从右侧临时抽屉打开，包含名称、用途、可用状态与预览；不常驻占用空间。未配置天气时仍可添加天气块，但有就近配置入口。

区块注册表建议包含：类型、标题、默认尺寸、最小尺寸、允许实例数、刷新策略、配置项、能力依赖和版本。布局只保存引用、位置、大小、折叠与展示配置；API Key、原始剪贴板正文和聊天历史不写进布局文件。

重复时钟或天气可以有独立展示配置，但共用数据源。专注计时等单实例业务只允许一个真实会话，多面板显示同一状态，不能制造多个互不一致的计时器。

### 6.4 持久化与恢复

保存 workspaceVersion、pageId、widgetInstanceId、布局断点和视图配置。窗口缩小保存独立断点布局，不破坏宽窗口排列。恢复旧版本时识别不存在的区块类型并给出替换或移除提示，不让整个页面空白。

提供本次编辑撤销、取消与恢复默认三种不同动作。恢复默认不清空用户数据。离开编辑页时有草稿处理逻辑，不能静默丢掉正在编辑的布局。

## 7. 视觉设计系统

### 7.1 颜色角色（建议 token）

| 语义 | 星夜 | 雪白 |
|---|---|---|
| 主画布 | #0B1220 | #F5F7FA |
| 工作表面 | #121D2D | #FFFFFF |
| 浮层 | #1A293D | #FFFFFF |
| 主要文字 | #E8EFF8 | #253B4E |
| 次要文字 | #A6B5C8 | #526678 |
| 辅助文字 | #899BB3 | #657887 |
| 结构边界 | #2D3D53 | #DCE4EB |
| 强调 | #9DCBEE | #286F98 |
| 强调底面 | #233B51 | #EAF3F8 |
| 焦点轮廓 | #B5DDFA | #1C648F |
| 成功文字 | #A2D2BF | #237254 |
| 警告文字 | #E1C292 | #825C21 |
| 错误文字 | #F0A7B5 | #A12E4D |

表面边界只是装饰性分隔，不能承担唯一的控件识别。输入框、开关轨道、选中态等非文字交互标记，另使用满足至少 3:1 的边线或状态差。普通文字目标至少 4.5:1，大字至少 3:1，实施时按实际组合与透明度复测。

雪白、银雾、冰蓝、星夜使用同一语义 token。银雾和冰蓝只调中性色倾向与底色，不能连错误、成功含义一起染色。默认主题仍待用户确认，不因前次展示深色稿就假定已批准切换默认值。

### 7.2 字体、间距与材质

- 中文沿用可本机稳定显示的 Microsoft YaHei UI / Microsoft YaHei；英文优先 Segoe UI Variable / Segoe UI。不为了“高级感”强装无中文字体。
- 页面标题 24–28px / 600，分区标题 16–18px / 500–600，正文和操作 14–15px / 400，元数据 12–13px。重要操作不依赖 10px 字。
- 时钟可 40–48px，使用 tabular-nums；CPU、内存、时长列数字右对齐。
- 英文诗句可用 Georgia Italic，14–16px，每屏最多一处；作者与出处可见。诗句不用作错误或配置说明。
- 间距以 4px 为基，常用 8、12、16、24、32。导航约 184–208px，主区边距 24–32px；小窗口缩小留白而非压小文字。
- 按钮和输入圆角 6–8px，普通面板 10–12px，浮层 12–14px。圆角表达层级，不把所有容器都胶囊化。
- 银色通过明度、细边缘和准确间距表现，不画金属纹理、反光拉丝和大量渐变。
- 静态面板无外阴影；菜单和对话框用轻阴影表达浮层。大面积 backdrop-filter 不作为材质基础。

### 7.3 按钮与组件约束

主按钮用于本页当前任务，不要求每张面板都有一个。次级操作采用中性描边或文字；破坏性操作用文字与明确命名，避免只放红色图标。

图标保持同一套 16–20px 线性风格，以现有 Icons 组件为起点。无标签图标须有可访问名称和悬浮说明。开关用于立即生效的布尔选项；提交动作使用按钮，不能用开关伪装。

面板标题栏可以统一，但内部按照任务变化：媒体是播放条，系统是数值行，今日足迹是时间线，聊天是消息流，设置是表单。丰富度来自不同的信息组织，不是换不同阴影。

## 8. 星辰与动态规范

### 8.1 星辰是环境，不是主内容

建议由一层独立 Canvas 绘制，不用大量 DOM 粒子。置于内容之下，pointer-events 为 none；不能盖住输入框、诗句、数值和正文。

以 1440×900 为起点：约 24–40 个远景点、6–10 个中景点、2–4 个很弱近景点；大部分静止，只少数慢移和明灭。粒子尺寸约 0.6–1.8 CSS px，亮度受限，不画星芒阵列、自动连线或跟随鼠标喷射。数量是设计预算，实施后再测性能与观感。

漂移约 0.3–1.2px/s；明灭周期约 9–18s，错相且不完全消失。局部空间主要围绕角色舞台与页面边缘，聊天阅读、设置长表单减少或关闭。多动态不意味着每个面板都运动。

### 8.2 动效层级

| 变化 | 建议时长 | 视觉反馈 |
|---|---|---|
| 悬浮、按下、焦点 | 100–140ms | 颜色或边界，按下不缩整块内容 |
| 子页切换 | 140–180ms | 轻淡入，最多 4px 位移，保留滚动 |
| 菜单展开 | 120–160ms | 从触发点出现，文字保持清楚 |
| 抽屉与详情区 | 180–220ms | 位置解释空间关系，无长距离弹飞 |
| 面板拖动和缩放 | 实时跟手 | 占位与吸附目标即时反馈 |
| 释放后的布局收敛 | 100–160ms | 无过冲，不让整页果冻回弹 |
| 完成与成功 | 160–240ms | 局部一次确认，不满屏庆祝 |
| 角色预览 | 继承现有角色运行节奏 | 不重复施加第二套 CSS 呼吸造成变形 |

界面弹性只用在很小的用户触发反馈；宠物自身可以果冻碰撞，但这不是让整个设置窗口也弹跳的理由。出生消失、翻滚、睡眠等动作不在本次 UI 文档阶段改写。

### 8.3 性能与减少动态

目标：在声明的测试设备上交互尽量接近 60fps；拖动面板时无可感知排队或输入丢失。星辰可 24–30fps，DPR 上限建议 1.5，窗口最小化、不可见、节能或减少动态时暂停。布局编辑期间可停背景动画，优先保证跟手。

不在每个动画帧更新整个 React 树，不同步高频轮询系统进程。布局拖动阶段以变换与占位预览，结束后持久化；业务计时、桌宠动作和音频采样保持自己的数据源，不因渲染减少而改业务时间。

这些是验收目标，不是已完成的性能测试结果。

## 9. 右键菜单设计

目标：在鼠标附近完成对话、翻译或打开工作台，然后迅速回到桌面。

结构固定为「一句状态 → 快捷输入 → 划线翻译 → 打开工作台 → 保存并退出」。宽度建议 300–340 CSS px，高度随内容收敛，避免目前预览中的长空白。长状态最多两行。

快捷输入 2–3 行即可，附件与复杂参数留到工作台。聊天发送后菜单可显示短回复或明确转入气泡，不能同时在两个窗口重复播放整段消息。按 Esc 关闭，焦点回到合理位置；点击外部关闭时保留草稿。

中文输入必须在真实 Electron 窗口验证。compositionstart 到 compositionend 之间的 Enter 不能发送；输入期间不能触发拖窗、透传或全局快捷键。菜单打开时的焦点和 click-through 行为需要单独确认。

菜单靠近屏幕边缘时换向定位，并限制在可用工作区内。星辰只容许少量静态背景点，输入期间停装饰漂移。不增加动作库、CPU 等全部功能入口，否则菜单会重新膨胀成小工作台。

## 10. 状态、隐私与真实数据

| 场景 | 应呈现 | 禁止 |
|---|---|---|
| 无数据 | 简短原因与开始方式 | 用示例数字伪装实时 |
| 加载 | 稳定骨架或局部进度 | 整页遮罩和持续闪动 |
| 服务断开 | 明确哪个服务断开，可重试 | 只把圆点变红 |
| 天气失败 | 最后更新时间与旧数据标记 | 把过期天气当实时 |
| 保存失败 | 保留草稿、重试或恢复原值 | 显示成功但未持久化 |
| 当前动作未知 | 状态暂不可用 | 推测成站立待机 |
| 模型不支持视觉 | 说明 OCR 仅提取文字 | 宣称模型已看懂整张图 |
| 日总结数据不足 | 展示覆盖范围，允许补充 | 默认记录键盘、截图、网页正文 |
| 事件推断 | 标出推断来源 | 硬写下载或编译成功 |

每天总结的采集项、保留时长、模型发送范围需要用户可控。云端摘要涉及发送本地活动信息时，界面应让用户知道将发哪些内容。默认不把剪贴板正文、Key 或聊天全文用于总览摘要。

## 11. 响应式、DPI 与可访问性

1440×900 是主要设计验收尺寸；补查 1280×800、1024×768 和高 DPI。按 CSS px 设计，实际测试 100%、125%、150%、200% 缩放。不能只把 1800px 预览图整体缩放当作小窗方案。

宽窗展示主区加侧区；中窗减少列数；窄窗子页签可横向滚动，检查区下移。侧栏可折叠为抽屉，但五个标签仍可见。正文页避免横向滚动，代码、表格等局部允许独立滚动。

布局编辑必须有非拖动替代；菜单、标签、对话框可用键盘；焦点明确，折叠后隐藏控件不能仍接收 Tab。状态更新避免持续抢读屏，计时器不每秒播报。不要用颜色单独表达健康、失败、连接或活动状态。

## 12. 组件与技术落点

这是提议的拆分，不是已经存在的完整实现。

- WorkbenchShell：五栏导航、窗口框架、子页与草稿恢复。
- OverviewWorkspace：受控的区块布局与默认布局。
- WidgetFrame / WidgetRegistry / WidgetLibrary：面板容器、能力声明、添加抽屉。
- CompanionStatus：只消费角色运行状态，不自己猜测动作。
- CharacterStage / Inspector：复用现有 CharacterPreview 与动作资产。
- AssistantWorkspace：复用连接、附件和会话能力，重排信息层级。
- ToolListDetail：剪贴板与待办可共享布局骨架，不共享混乱业务状态。
- SettingsSection / SettingsRow：复用现有开关与输入控件，补齐失败与保存反馈。
- AmbientStars：在已有 StarField 基础上限速、按页配置、按可见性暂停。
- PetQuickMenu：独立紧凑布局，中文输入与窗口焦点单独验证。

保留 Electron + React/TypeScript 的当前入口及桌宠后端。App.tsx、workbench.css、CharacterPreview.tsx、ActionLibrary.tsx、AssistantWorkspace.tsx、MusicWorkspace.tsx、FutureWorkspace.tsx、SelectionTranslation.tsx、SettingControls.tsx、StarField.tsx 是后续核对与拆分起点。现有代码含旧入口或依赖不代表此次要恢复 Tauri，也不顺手清理与设计无关的运行路径。

布局方案先比较原生 CSS Grid 加指针交互与成熟布局库的兼容成本，再决定；不能在本次设计文档阶段未经验证锁定依赖。若使用库，要验证 React 19、Electron 44、高 DPI、键盘替代和持久化。图标、字体与额外 UI 库同样优先复用现有资源。

### 验收清单

- 五栏结构准确；子页有唯一归属；工具第四项没有擅自定案。
- Yuki 的原比例、原画风和完整透明边缘保留；动作预览不改变真实运行状态。
- 当前状态、预计下一步、配置与数据来源区分清楚。
- 正常模式无多余拖柄；编辑可拖可缩、可取消可恢复；隐藏不删除数据。
- 新建、重命名、删除自定义页不会影响业务记录。
- 每个数据块都有未配置、加载、为空、成功、失败、过期的适用状态。
- 中文输入、Enter 发送、失焦、关闭菜单、贴屏边缘不出错。
- 主题与 DPI 下文字可读、控件无裁切、键盘焦点清楚。
- 星辰可关闭，最小化暂停，不影响拖动、媒体控制或模型输入。
- 真实服务缺失时如实提示，演示数据始终标记。
- 功能与代码验收只在实现阶段执行；本轮不将文档审查冒称运行验证。

## 14. 本轮设计决策与待确认项

建议保留：固定五栏、对象优先的角色舞台、任务差异化页面、实色面板、明度层次、少量英文题记、低密度星尘、显式布局编辑模式。
