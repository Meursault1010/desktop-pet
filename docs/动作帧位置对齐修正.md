# 动作帧位置对齐修正

## 问题

部分生成动作的关键帧虽然画布尺寸一致，角色在透明画布中的实际位置却不同。逐帧播放时，角色整体会左右或上下跳动，看起来像动作断帧。

## 修正

- 对生成的多帧定点动作逐帧测量可见像素范围，以序列中位数水平中心和共同落点作为对齐锚点。
- 绘制时只平移角色图像，不移动宠物窗口；相邻姿势之间按动作过渡进度插值补偿量。
- 除关键帧外，逐张测量已有光流插帧的锚点，覆盖 117 组过渡，避免中间帧非线性漂移。解码未就绪时只使用当前原帧的补偿，不提前向下一帧滑动。
- 保留有意位移：侧滚及地面坐/趴待机不做画布校正；抛飞、碰撞和跳跃动作不做校正；庆祝动作只修正水平画布漂移，保留腾空高度。
- 对齐偏移写入 `console-v2/assets/actions/frame-alignment.json`，由 `build_frame_alignment.py` 从源帧可重复生成。

## 验收

`console-v2/test_action_alignment.py` 检查配置与素材一致、校正后的锚点、帧间偏移插值以及位移动作排除规则。验证命令：

```powershell
cd console-v2
python -m unittest test_action_alignment
```

`console-v2/qa_frame_alignment.py` 生成代表动作的原始/校正对照图到 `.electron-build/frame-alignment-preview.png`，便于检查校正是否裁切角色或抹掉姿势变化。

`console-v2/qa_alignment_render.py` 通过实际 Qt 绘制器以 30fps 输出等待、工作和打哈欠的对比，并验证延迟解码回退。以下是对比画面中角色可见轮廓中心的横向范围（渲染像素；不是窗口位移）：

| 动作 | 原始横向范围 | 校正后横向范围 | 校正后落点范围 |
| --- | ---: | ---: | ---: |
| 等待 | 51px | 0.5px | 0px |
| 工作 | 38.5px | 1px | 0px |
| 打哈欠 | 32px | 1px | 0px |

这项修正针对画布位置漂移，不改变原图大小、姿势和动作播放频率；原始姿势间的解剖或造型差异仍可能可见。全量测试发现其他未通过项：构建环境缺少离线用 Pillow；尺寸校准测试没有新飞行图集的报告且碰撞帧不满足旧站姿高度断言；图标裙摆遮罩及安静呼吸唯一采样数断言未通过。它们未被当作本次对齐修复的已通过项。

## 发布与结果

- 对齐专项 3 项通过；相关播放器、插帧、待机、巡逻、点击拖拽及碰撞测试共 105 项断言通过。后者 unittest 输出 OK，但 Qt 测试进程退出码为 1，因此未记为完整进程通过。
- 独立正式包 Electron 冒烟 18 项通过，退出码 0，后端正常退出，无界面控制台错误；源码、可读资源目录和冻结后端内部资源的对齐 JSON SHA256 一致。
- 发布目录：`releases/electron/yuki-win32-x64-frame-aligned/yuki-win32-x64`。`start-electron.bat` 优先启动此包。当前运行中的旧进程未终止，需保存退出后重新启动才能使用修复。
