# Yuki 侧滚分帧位移

日期：2026-10-19。

按用户反馈，侧躺时保持桌面位置，只有翻身动作发生时才移动。旧算法按帧编号均匀分配位移，侧躺整理表情的帧也分到了移动距离，因此像躺着滑行。

现在为两套实际图集分别标定位移相位。下表使用从 1 开始的图片帧号，数值表示单次完整翻身已经完成的位移比例。

| 图集 | 各帧累计位移比例 |
| --- | --- |
| 正向 toward | 0、0、0.12、0.28、0.45、0.62、0.80、0.94、1、1、1、1 |
| 反向 away | 0、0、0、0、0.06、0.20、0.38、0.55、0.72、0.88、1、1 |

正向的第 1→2 帧、第 9→12 帧，以及反向的第 1→4 帧、第 11→12 帧仅有侧躺或细小姿态变化，窗口位置恒定。进入相邻翻身姿势之间的过渡时，位移与绘制器使用同一过渡进度，在姿势已经转动时才移动，不在帧边界突然跳坐标。站立到趴下的入场段也保持原位。

反向素材是正向关键姿势的倒序排列，所以两者分别标定，不能套用相同的帧号。跨完整循环保留累计位移，结束侧躺停留不再滑行。普通待机、手动动作和自主巡逻共用 `ActionPlayer.roll_progress()`，方向、边界避让和总距离保持既有行为。

本轮 40 项播放器、随机待机与巡逻测试通过，新增覆盖两方向、不同播放速度、多次随机周期，以及真实 Qt 窗口在侧躺区间坐标不变。实际绘制器导出每方向 279 帧预览：
